# 比赛现场代码修改说明

> 版本：vibmon_v5　日期：2026-10-31
> 用途：现场需要临时改 LED、串口、输出协议、采样或阈值时，快速定位修改点并复验
> 原则：**先明确组委会/平台要求，再改代码；每改一处必须编译 + 主机测试 + 实板短测**

---

## 1. 现场修改总原则

1. 所有可调参数优先改 `config.h`，不要直接改 `.cpp`。
2. 修改前先保存当前提交号：

   ```powershell
   git log -1 --oneline
   git status --short
   ```

3. 只做“现场必须改”的项，不要顺手重构。
4. 每次修改后按顺序验证：

   ```text
   1. 主机测试
   2. 双 FQBN 编译
   3. 烧录
   4. S 状态检查
   5. 静态/动态短测
   ```

5. 修改后建议立即提交本地 Git，保留可回退点。

## 3. LED 修改说明

### 3.1 当前引脚

```c
#define PIN_LED_G      10        // 绿：心跳
#define PIN_LED_Y      5         // 黄：振动中 / 故障快闪
#define LED_ACTIVE_LOW 0         // 1 = 灌电流接法
```

红色 LED 由 5V 硬件常亮，表示稳压输出正常，不在固件里改。

### 3.2 修改 LED 引脚

如果现场接线或模块封装导致必须换脚：

1. 打开 `config.h`；
2. 修改 `PIN_LED_G` 或 `PIN_LED_Y`；
3. 确认新 GPIO 没有被 I2C、串口、strapping 或其它器件占用；
4. 编译并烧录；
5. 用 `S` 确认系统运行；
6. 观察 LED 状态是否符合下表。

### 3.3 修改 LED 逻辑

当前逻辑在 `output.cpp` 的 `ledUpdate()`：

| 模式 | 绿 LED | 黄 LED |
|---|---|---|
| `LED_RUN` | 1Hz 闪烁 | 振动中常亮 |
| `LED_CAL` | 常亮 | 常亮 |
| `LED_FAULT` | 灭 | 4Hz 快闪 |

如果组委会要求黄灯表示“接触”而不是“振动中”，可在 `LED_RUN` 分支中把：

```c
ledWrite(PIN_LED_Y, r.vib == 1);
```

改为：

```c
ledWrite(PIN_LED_Y, r.contact == 1);
```

如果要求黄灯表示“已闭合”：

```c
ledWrite(PIN_LED_Y, r.closed == 1);
```

不要把故障态的黄灯快闪删掉；它是现场判断 I2C/MPU 掉线的重要提示。

### 3.4 绿灯改为灌电流接法

如果现场绿灯极暗或不亮，且已换备用灯仍无效，硬件飞线改成灌电流后，必须修改：

```c
#define LED_ACTIVE_LOW 1
```

再重新编译烧录。否则 GPIO 电平逻辑相反，LED 状态会全部反转。

## 4. 串口修改说明

### 4.1 当前配置

调试口：

```c
#define BAUD 115200
```

比赛口：

```c
#define PIN_COMP_TX 21
#define PIN_COMP_RX 20
#define COMP_BAUD   115200
```

默认 4pin 线序：

```text
①TX = GPIO21
②RX = GPIO20
③GND
④VIN = 12V
```

### 4.2 修改调试口 TX/RX

若现场确认接线方向相反，改：

```c
#define UART_SWAP 1
```

效果：

```text
PIN_DEBUG_TX 20
PIN_DEBUG_RX 21
```

改完必须重新编译烧录，并重新确认串口有输出。

### 4.3 修改波特率

调试口和比赛口波特率是分开的。

调试串口：

```c
#define BAUD 115200
```

比赛串口：

```c
#define COMP_BAUD 115200
```

如果平台要求 9600，只改 `COMP_BAUD`；不要把调试口也一起改，否则现场调试工具需同步调整，容易引入混乱。

### 4.4 启用比赛帧

默认比赛口完全静默：

```c
#define COMP_FRAME_ENABLED 0
```

与平台确认协议后改为：

```c
#define COMP_FRAME_ENABLED 1
```

重新编译烧录后，比赛口会输出 35 字节定长帧：

```text
$VD,SEQ,FREQx10,AMP_MG,VIB,CT,SSx100,VALID,CHK\r\n
```

### 4.5 修改帧字段

如果平台要求不同字段，优先修改 `output.cpp` 中的 `compBuildFrame()`。

相关辅助函数：

| 函数 | 作用 |
|---|---|
| `encFreqX10()` | 主频转 0.1Hz 整数 |
| `encAmpMg()` | 幅值转整数 mg，并饱和 |
| `encSsX100()` | 启停频率转 0.01Hz 整数 |
| `encValid()` | 有效性位图 |
| `xorChk()` | XOR 校验 |

修改帧格式后必须同步更新：

1. `vibmon_v5/test/comp_frame_test.cpp`
2. `串口帧协议草案.md`
3. `现场输出文档.md`

并运行：

```powershell
g++ -std=c++17 -Wall -I test -I . `
  test\comp_frame_test.cpp output.cpp state.cpp dsp.cpp `
  -o test\comp_frame_test.exe

.\test\comp_frame_test.exe
```

## 5. 采样与算法参数修改

### 5.1 采样率

```c
#define FS_HZ 1000
```

不建议现场修改。如果必须修改：

1. `FS_HZ` 不能超过 1000；
2. 必须仍满足 `FREQ_HI_HZ < FS_HZ / 2`；
3. 陀螺积分步长会随 `GYRO_DIV / FS_HZ` 改变；
4. 必须重跑主频、启停、陀螺测试。

### 5.2 I2C 速率

```c
#define I2C_CLOCK 200000UL
```

若现场 I2C 错误持续增加，可尝试：

```c
#define I2C_CLOCK 100000UL
```

但先检查硬件：

- SDA/SCL 焊点；
- 排线根部；
- 3V3/5V/GND；
- 弯折应力；
- 接插件接触。

降速只是缓解，不是修复物理连接。

### 5.3 接触阈值

当前默认：

```c
#define CT_FLAT_A_ON_MG   400.0f
#define CT_FLAT_A_OFF_MG  300.0f
#define CT_FLAT_F_ON_HZ   78.0f
#define CT_FLAT_F_OFF_HZ  65.0f
```

修改浮点门限时必须同步修改整数镜像
`CT_FLAT_F_ON_HZ_INT` / `CT_FLAT_F_OFF_HZ_INT`，否则编译期检查仍按旧值。

现场只有在拿到足够数据后才建议修改。至少要有：

```text
空握 A/F 分布
接触振动 A/F 分布
静止物体 A/F 分布
```

并把类间差保持在组内离散度的 3 倍以上。

### 5.4 闭合角阈值

当前：

```c
#define ANGLE_CLOSED_DEG     60.0f
#define ANGLE_CLOSED_OFF_DEG 45.0f
```

不要为了夹不住的 5cm 方块降低阈值。最终验收应使用 4cm 正方形物体；5cm 只作为临时振动源。

## 6. 编译与烧录命令

### 6.1 双 FQBN 编译

推荐始终跑两个目标：

```powershell
$cli = "C:\Users\Lenovo\AppData\Local\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe"
$src = "D:\大学\课程\工科赛\代码\vibmon_v5"

& $cli compile --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc" $src --warnings all
& $cli compile --fqbn "esp32:esp32:esp32c3" $src --warnings all
```

正常应显示 0 warning。

### 6.2 烧录

假设模块在 `COM8`：

```powershell
$cli = "C:\Users\Lenovo\AppData\Local\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe"
$src = "D:\大学\课程\工科赛\代码\vibmon_v5"

& $cli upload --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc" `
  --port COM8 $src
```

如果现场 COM 号变化，先用：

```powershell
& $cli board list
```

确认。

### 6.3 串口打开会复位

ESP32-C3 USB CDC 打开串口时可能复位开发板。烧录后先等待：

```text
上电 0.3s
MPU 初始化
标定 3.2s
START 基线采集
```

不要一打开串口就开始动作测试。

## 7. 现场修改后验证流程

每次改代码后按固定流程验证：

### 7.1 主机测试

```powershell
cd D:\大学\课程\工科赛\代码\vibmon_v5

g++ -std=c++17 -Wall -I test -I . `
  test\gyro_test.cpp dsp.cpp state.cpp `
  -o test\gyro_test.exe

.\test\gyro_test.exe
```

要求：`6/6` 通过。

如果改了比赛帧：

```powershell
g++ -std=c++17 -Wall -I test -I . `
  test\comp_frame_test.cpp output.cpp state.cpp dsp.cpp `
  -o test\comp_frame_test.exe

.\test\comp_frame_test.exe
```

要求：`22/22` 通过。

### 7.2 编译

跑 CDC 与非 CDC 双 FQBN，均应 0 warning。

### 7.3 烧录

使用 `esp32:esp32:esp32c3:CDCOnBoot=cdc` 烧录，保证 USB 调试串口可用。

### 7.4 上电检查

串口 115200 打开，确认：

```text
红色 LED 常亮
绿色 LED 闪烁
MPU 就绪
标定有效
无 I2C 错误
```

发送 `S`，重点看：

```text
I2C错 = 0
读失败 = 0
不连续 = 0
传感器在线
```

### 7.5 动作短测

```text
1. START 静止：ang≈0，closed=0，ct=0
2. 空握：closed=1，ct=0
3. 接触振源：A>400，F>78，ct=1
4. 关闭振源：ct 短时间内回到 0
5. 回 START：closed=0
```

若出现：

```text
[FAULT] 传感器无响应
A=?
ang=?
I2C错>0
读失败>0
```

本轮数据作废，先查硬件，不要继续调算法。

## 8. 不建议现场修改的项目

| 项目 | 原因 |
|---|---|
| 采样架构 | 涉及定时器、I2C、环形缓冲和时序，必须完整回归 |
| 标定流程 | 改错会引入零偏漂移 |
| 比赛帧长度和字段顺序 | 平台侧可能已按固定格式解析 |
| `contact` 判据结构 | 当前已有实测依据，现场无充分数据时容易引入误报 |
| `posture` 接入正式 `contact` | 该模块目前只做诊断，证据不足 |
| 神经网络/加权模型 | 数据量和现场时间都不支持 |

## 9. 现场回退策略

如果修改后无法在 10 分钟内恢复功能：

1. 停止继续改代码；
2. 回到最近一次可运行提交：

   ```powershell
   git log --oneline
   git checkout <上一个可运行提交> -- vibmon_v5
   ```

   或使用已保存的稳定源码目录重新烧录；

3. 重新执行编译和短测；
4. 先保证比赛演示，再讨论算法优化。

不建议在赛场上做大范围重构或同时修改多个参数。

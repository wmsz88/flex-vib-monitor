## 一、总体方向判断：✅ 正确

代码的核心设计思想是把两类物理量分开处理：

| 物理量 | 传感器 | 判据 | 回答的问题 |
|---|---|---|---|
| **机械姿态** | 陀螺积分 | `closed = θ > 60°` | "手指合拢了没有" |
| **振动传导** | 加速度高通 | `A > 400mg 且 F > 75Hz` | "合拢后是否接触振动物体" |

这个"姿态+振动双轴独立"的架构避免了经典陷阱：把"手指合拢"误判为"夹到东西"。从实板数据和宿主测试（`contact_test` 43/43、`gyro_test` 8/8、`comp_frame_test` 22/22）来看，方向验证通过。

### 2.1 `config.h` — ✅ 优秀

- 编译期检查 40+ 条，覆盖采样率、频段、NG 阈值、滞回方向
- 每个宏都有注释解释"为什么是这个值"和"改了会怎样"

- 存在已废弃但未清理的部分：模式 3 的 `CT_FLAT_D_ON_MG`/`CT_FLAT_D_OFF_MG` 及其整数镜像宏在模式 4 下不再使用，但不影响编译

### 2.2 `state.cpp` — ✅ 核心逻辑正确

**正确的设计决策（高分项）：**
1. `postureInput()` 的兜底（:360-363）：角度失效时用 `flatDist` 代替，避免陀螺短暂失效导致 `contact` 直接掉 0
2. `combineContact()` 的保持规则：进入需三路全真，保持只需姿态+(幅值或频率)，避免间歇激励把接触切碎
3. `CT_FLAT_DEGRADE_STRICT=1`：数据失效时保守处理
4. FINDING-01/04 已修复，`contact_test` 43/43 全过

**⚠️ 注意：AUTO_ZERO 可能在比赛中制造意外**
- 触发条件：`s_sinceClose=true` + 静止≥2s + 幅值<100mg + 闭合角<8°
- 如果比赛操作中手指偶然停在张开位附近 2s，基准会被悄悄更新
- 建议比赛前确认：操作流程中是否会有"张开+静止>2s"的非预期窗口

### 2.3 `dsp.cpp` — ✅ 信号链路正确

- 70Hz 二阶 Butterworth 高通：`HP_FC_HZ=70`, `HP_Q=0.7071`，设计合理
- 过零周期估计 + 中位数频率：`estimateFreq()` 做了周期有效性检查（tMin/tMax/MIN_PERIODS）
- `FREQ_LO_HZ=60`, `FREQ_HI_HZ=220` 覆盖赛题 80-180Hz
- 削顶分级：主轴 ≥10% → 主频失效 (`CLIP_SEVERE`)，任意轴 → 幅值失效
- 标定流程：两阶段（偏置 2s + 噪声 1.2s），全部校验通过才提交

### 2.4 `output.cpp` — ⚠️ 比赛帧缺少 `closed` 字段

当前 `$VD` 帧（35 字节）：
```
$VD,SEQ,FREQx10,AMP_MG,VIB,CT,SSx100,VALID,CHK\r\n
```

缺失：`closed`（手指是否闭合）不在帧里。如果测试平台需要区分三种情况：
- "手没合" → `closed=0`
- "手合了但没振动" → `closed=1, ct=0`
- "手合了且有接触" → `closed=1, ct=1`

当前帧只能表达最后一种。详见建议 1。

### 2.5 `mpu.cpp` / `sampler.cpp` — 未深入评审

I2C 驱动层和采样器代码本次未逐行评审。从 `当前状态.md` 的记录看，它们面临的挑战不在代码层面而在物理连接可靠性。

### 2.6 主程序 `vibmon_v5.ino` — ✅ 编排合理

- 上电流程：串口 → DSP 初始化 → MPU 初始化 → 标定 → 启动采样 → START 基线采集
- 主循环数据流顺序正确：`samplerPop → gap通知 → dsp → state → posture → output`
- 故障恢复：1s 重试，恢复后沿用旧标定（如果旧标定有效）
- 标定失败时的兜底：用编译期默认参数，每 5s 自动重试

## 四、三个建议改动（赛前）

### 建议 1：比赛帧增加 `closed` 字段（低风险，1 个文件）

在 `output.cpp` 的 `compBuildFrame()` 中增加 `CL` 字段（1 位）：
```
$VD,SEQ,FREQx10,AMP_MG,VIB,CT,CL,SSx100,VALID,CHK\r\n
```
从 35 字节变为约 37 字节。同步更新 `comp_frame_test.cpp`。

**前提**：现场平台确认帧格式可调整。如果平台已约定 35 字节固定，则不改——但要在答辩中说明"CT=0 时需结合现场观察判断是松手还是空握"。

### 建议 2：确认 `COMP_FRAME_ENABLED=1` 是最终配置

当前工作区已冻结为 1（比赛口持续发送）。到场后如果平台要求先不发数据，需能快速改回 0 并重烧。

### 建议 3：新增 `D` 命令（DUMP 模式，中风险）

新增一条 `D` 命令：输出一行包含全部原始字段的 CSV，比 `#SWEEP` 更全，包含 `closed`, `flatDist`, `closeAngleDeg`, `condPosture`, `condAmp`, `condFreq`。现场调试时一条命令就能看出三路中哪一路卡住了。

涉及文件：`output.cpp`, `output.h`。

## 五、最大风险

**不是代码，是 MPU6050 I2C 物理连接。**

`当前状态.md` 记录了真实动作中间歇掉线：
- `I2C错 587，读失败 505`（30 秒轻微弯折测试）
- `[FAULT] 传感器无响应`（4cm 圆柱测试中复现）
- 重新烧录只能暂时恢复，不能根治

**赛前必须完成**：检查 SDA/SCL/3V3/GND 焊点和接插件；静止 60s + 动态弯折 30s 均 `I2C错=0`。

## 4. 问题清单

### P2 / FINDING-01：`CT_MODE=4` 缺少 `flatRefSet` 门控

**现象（可复现）**：没有采到平放基准、或基准采集因“在动”被拒绝后，只要来一帧
带陀螺的 `DspFrame`，`contactValid` 就变成 `1`，而 `flatRefSet` 仍为 `0`。

**证据**：

```text
[PASS] C1 未采基准：flatRefSet=0
[PASS] C1 未采基准：当前实现 contactValid=1（FINDING-01，文档约定为 0）
[PASS] C3 采集在动：flatRefSet=0
[PASS] C3 采集在动：当前实现 contactValid=1（FINDING-01，文档约定为 0）
```

**根因位置**：

```text
state.cpp:351  static bool postureInput(...)
state.cpp:352  #if CT_MODE == 4
state.cpp:354    return s_r.angleValid;      // 没检查 s_flatRefSet
state.cpp:372  if (!postureInput(...)) { ... contactValid=false; return; }
state.cpp:427  s_r.contactValid = true;      // 三门输入可用即置 true
state.cpp:630  flatRefCommit() 里 flatRefSet 才置 true
state.h:24     contactValid 注释只写了 CT_MODE=2/3 的语义
```

**影响**：

- 上电后约 0.8s 基准采集窗口内，或基准采集失败时，`contact=0` 会被标成
  “结论可信”；
- 如果设备上电时已经夹住，闭合角从 0 起算，可能输出 `closed=0` 且
  `contactValid=1`；
- 模式 3 的约定是“没有可信基准不得输出接触结论”，模式 4 当前行为与该约定
  不一致。

**建议**：二选一，但只选一个，避免双重门控：

1. 推荐：在 `postureInput()` 的 `CT_MODE == 4` 分支返回
   `s_r.angleValid && s_flatRefSet`；
2. 或者：保持 `postureInput()` 只回 `angleValid`，但在 `ctStep` 进入三门前
   单独用 `s_flatRefSet` 判断，不通过则按现在的早退块置
   `contact=0, contactValid=false`。

修改后需要：

- 把本报告 C1/C3 的期望改回“`contactValid=0`”；
- 重跑 `gyro_test`、`comp_frame_test`、`contact_test`；
- 重跑双 FQBN 编译，确认 0 warning。

### P2 / FINDING-04：判据输入失效时 `closed` 保留旧值

**现象（可复现）**：先建立 `contact=1`，再让陀螺中断超过 `GYRO_STALE_MS`，
`angleValid`/`contactValid` 都会归零，`contact` 也会变 0，但 `closed` 仍保持
上一轮的 `1`。

**证据**：

```text
[PASS] C12 陀螺失效：angleValid=0
[PASS] C12 陀螺失效：contactValid=0
[PASS] C12 陀螺失效：contact=0
[PASS] C12 陀螺失效：当前实现 closed=1（FINDING-04，语义应为 0）
```

**根因位置**：

```text
state.cpp:372  if (!postureInput(...)) {
state.cpp:376    s_r.contact = 0;
state.cpp:384    s_r.contactValid = false;
state.cpp:385    return;                 // 没有写 s_r.closed = false
state.cpp:445  s_r.closed = (s_ctPostCmd != 0);  // 只在三门路径里更新
```

`closed` 全工程只有 `state.cpp:445` 一处赋值；判据输入不可用时走早退块，
所以它不会被更新，保留上一轮的值。

**影响**：

- 调试口 `S` / 运行状态会显示 `closed=1, contact=0, contactValid=0`；
- 上电未采基准（FINDING-01）或陀螺中断时，上位机若只看 `closed` 会以为
  “姿态门仍成立”；
- 比赛帧不直接编码 `closed`，所以不影响 `$VD` 帧字段，但影响现场判读。

**建议**：在 `state.cpp:372` 的早退块里补一行：

```c
s_r.closed = false;
```

若同时采纳 FINDING-01，这里还应考虑把 `s_ctPostCmd = 0;` 一起清掉，
让下次判据恢复后重新过姿态门，而不是沿用中断前的门状态。

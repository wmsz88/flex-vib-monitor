# AGENTS.md — vibmon_v5 多模型协作分工（总规则）

> 所有模型开工前必须读本文件并严格遵守。本文件由两个规划模型共同维护。
> 分工一句话：**glm5.3 与 deepseekv4pro 都可进行规划与定方向，flash 负责执行任务；flash 无权更改规划文件夹，只能在任务结束后给出数据结论；规划模型通过数据和结论来推进完成任务。**

## 0. 角色分工

| 角色 | 模型 | 代号 | 职责 |
|------|------|------|------|
| 规划 | DeepSeek v4 pro | PLANNER-A | 定方向、拆任务卡、读数据结论、推进任务 |
| 规划 | GLM 5.3 | PLANNER-B | 同上：定方向、拆任务卡、读数据结论、推进任务 |
| 执行 | flash 模型 | EXEC | 执行任务卡、改代码、任务结束后交数据结论 |
| 场外 | Claude（Claude Code） | OUTSIDER | 人类直接授权的场外模型：自拟场外卡、改代码、交结果；只在人类点名时开工 |

两个规划模型权限完全对等：都能写 `规划/`（plan.md 与任务卡）、都能派卡、都能做推进判定。谁是"当前主规划"以 plan.md「规划日志」最新一条的署名为准。

## 0.1 模型行为详细规则

行为规则按模型大小分开存放，AGENTS.md 只保留总纲：

| 文件夹 | 受众 | 内容 |
|---|---|---|
| `大模型/` | PLANNER-A (deepseekv4pro) + PLANNER-B (glm5.3) | 规划模型行为规则、评审记录、方向决策 |
| `小模型/` | EXEC (flash) | 执行模型行为规则、需要执行的任务指令 |

**每个模型开工前额外必读**：
- 大模型（规划侧）→ 先读 `大模型/规则.md`
- 小模型（flash）→ 先读 `小模型/规则.md`

## 1. 写权限隔离（防混乱核心）

| 模型 | 唯一可写 | 禁止 |
|------|---------|------|
| deepseekv4pro | `AGENTS.md`、`规划/` 整个文件夹（plan.md + tasks/）、`大模型/` | 禁止改任何代码文件；`结果/` 只读；`小模型/` 只读 |
| glm5.3 | `AGENTS.md`、`规划/` 整个文件夹（plan.md + tasks/）、`大模型/` | 禁止改任何代码文件；`结果/` 只读；`小模型/` 只读 |
| flash | 根目录代码（`*.h *.cpp *.ino` 等）、`data/`、`test/`、`_probe/`、`结果/`、`小模型/` | **`规划/` 整个文件夹一律禁写、禁改、禁删**（读可以）；**`大模型/` 只读** |
| Claude（场外） | 根目录代码、`test/`、`data/`、`结果/` 下自己的 RT；`规划/tasks/` 下**自己起草的场外卡**；plan.md「规划日志」**只追加**、`AGENTS.md` 本行与 §1.2 | 不改其他卡的状态与验收、不推翻规划侧决策、不动 `大模型/` `小模型/` |

## 1.2 场外模型规则（2026-11-05 人类授权新增）

1. **来源**：只在人类直接点名时开工；规划侧不能给场外模型派卡。
2. **场外卡**：自拟卡标题带「（场外）」，卡内写明人类授权原话、改动范围、验收标准；与在办卡冲突时，不改对方卡，把分歧与数据写进自己卡的「与在办卡关系」和 plan.md 日志，由人类拍板。
3. **默认构建不变**：场外改动一律走编译期宏门控，默认值保持出发固件行为；改前改后跑全部宿主测试。
4. **交结果**：同 flash，`结果/RTxxx-YYYYMMDD.md` 只写做了什么、测到什么、结论；署名 `YYYY-MM-DD HH:MM · Claude (OUTSIDER)`。

## 1.1 规划侧防撞车规则（双规划新增）

1. **改动前先读**：任一规划模型改 `规划/` 前，先读 plan.md 的「规划日志」和各任务卡状态，确认没有另一侧正在推进的半成品（`doing` 状态的卡属于"当前主规划"）。
2. **每笔改动留痕**：改 plan.md 或任务卡状态，必须在「规划日志」追加一行（日期 + 署名 + 干了什么）。无日志的改动视为无效改动，另一侧可回滚。
3. **分歧写进文件**：两个规划模型方向判断不一致时，不争论，把各自理由写进 plan.md「风险点」或任务卡「备注」，由人类拍板。
4. **不推翻对方未过期的决策**：对方 3 天内做出的推进判定（卡状态、方向记录）不得直接推翻；认为有问题的，开新卡用数据说话。

│   ├── 规则.md        ← 小模型（flash）行为规则，开工前必读

## 3. 工作循环（推进机制）

任一规划模型（glm5.3 或 deepseekv4pro）都可以发起一轮：

1. **定方向**：读 `结果/` 中最新结论 + `规划/plan.md` → 决定下一步方向，写入 plan.md 的「规划日志」（署名）
2. **拆卡**：按方向在 `规划/tasks/` 起草任务卡 `Txxx-主题.md`（目标、涉及文件、验收标准、要求回传的数据）
3. **派卡**：把任务卡状态改为 `todo` 并在 plan.md 登记（此时自己成为"当前主规划"）
4. **flash 执行**：读当前任务卡（只读）→ 修改代码 → 任务结束后，按 `结果/_结果模板.md` 在 `结果/` 写 `RTxxx-YYYYMMDD.md`（只有数据与结论）
5. **推进判定**：读结果文件，对照验收标准——达标则在任务卡与 plan.md 标记推进、开下一张卡；不达标则开返工卡（注明返工原因）
6. 回到第 1 步循环

## 4. 防混乱铁律

1. **单一事实源**：方向只出自 `规划/plan.md`，数据结论只出自 `结果/`。两个文件夹之外任何内容（含对话记录、聊天上下文）都不是事实源。
2. **flash 的结论文件只写三样**：做了什么（文件级改动）、测到什么（数据）、结论是什么。**禁止**在结论里写"建议下一步""应该怎么规划"——推进决策权全在规划侧。
3. flash 禁止改 `规划/` 下任何内容，包括：改任务卡状态、勾选验收标准、改 plan.md。
4. **一次只推一张卡**：任务卡状态为 `doing` 时，其他卡不得开工，另一侧规划模型也不得开新卡。
5. 规划侧（两个模型都算）禁止直接改代码；发现代码问题 → 开新任务卡交给 flash。
6. 模型之间不直接对话，**唯一交流渠道是文件**：`规划/tasks/`（派活）、`结果/`（交活）、plan.md 规划日志（规划侧互相知会）。
7. 既有历史文档（`当前状态.md`、`代码测试报告_*.md`、各方案文档等）视为只读存档，不再更新；新内容一律进 `规划/` 或 `结果/`。
8. **行为与结果一律署名（日期 + 模型）**：大小模型的**每一次行为**（派卡、改卡状态、验收判定、评审、改规则文件）和**每一份结果**（RT 文件、数据目录、评审报告），都必须标注「日期 + 模型」：
   - 规划侧行为 → 写进 plan.md「规划日志」或任务卡「完成记录/备注」，格式 `YYYY-MM-DD HH:MM · 模型名 (角色)`
   - flash 行为与结果 → 写进 `结果/RTxxx-YYYYMMDD.md` 头部「执行模型 / 执行日期」字段，数据目录名含日期（如 `data\t004_20261102\`）
   - 无日期、无模型署名的记录视为无效记录，另一侧可要求补签后才承认

## 5. 命名规范

- 任务卡：`Txxx-主题.md`（编号三位数递增，如 T001、T002）
- 结果文件：`RTxxx-YYYYMMDD.md`（R 前缀 = Result，对应任务号）
- 任务卡状态只有三种：`todo` → `doing` → `done`

## 6. 任务卡与结果文件的对应关系

每张任务卡必须有对应的结果文件才能算完成；没有结果文件的任务卡，规划侧一律视为未完成，不得推进。返工时 flash 重新执行后写新的结果文件（新日期），旧结果文件不删除、留痕。

## 预案清单（规划侧拟定，flash 誊入手册时逐项核对补全）

> 每项 = 3 种情况参考 + 对应预案。改法均具体到宏/文件；「零改动」项也要写进手册（答辩口径）。

### 一、串口/帧协议（对接平台第一关）

**1. 帧格式**
- 情况A：平台直接读我们的帧 → **零改动**（$VD 35 字节 ASCII，T008 实板验证 3008/3008 校验错 0）
- 情况B：平台需要接触/闭合字段 → `COMP_FRAME_CL=1`（37 字节，T008 P2 已验证，一行宏重烧）
- 情况C：平台只认 CSV 文本行（同赛项 zongjisa 风格：无帧头无校验逗号分隔）→ 现场改 `compBuildFrame` 格式串（约 20 行；**建议本卡预写 `COMP_FRAME_CSV` 门控宏默认 0**，带上变体固件）

**2. 波特率**
- 情况A：平台 115200 → 零改动
- 情况B：平台要求 9600/4800 → `COMP_BAUD` 宏改一行重烧
- 情况C：平台自动适配/可配置 → 零改动，对接时现场调平台侧

**3. 帧率**
- 情况A：50Hz 现状可接受 → 零改动
- 情况B：平台嫌快（处理不过来/丢帧）→ 发送分频宏降 25Hz/10Hz（预写门控，默认不分频）
- 情况C：平台要求更快 → 受 DSP 窗口约束不提速，如实说明（50Hz 判据刷新已是设计值）

**4. 编码（GBK 类）**
- 情况A：平台 GBK 环境 → **零改动**，$VD 帧纯 ASCII（字母+数字+逗号+hex），任何编码可直接解析——**答辩标准口径**
- 情况B：平台串口工具显示乱码 → 切十六进制模式核对帧字节，是工具显示问题不是帧问题
- 情况C：平台要求中文应答 → 不做（历届六年无此要求，ASCII 是通用做法；若评委坚持，现场用 D 命令文本行应对）

**5. 发送使能/触发**
- 情况A：接上就发 → 零改动（现状）
- 情况B：平台要求静默待命（接错口/调试期）→ `COMP_FRAME_ENABLED=0`（比赛口完全静默）
- 情况C：平台命令触发式（发指令才开始发数据）→ 预案：加比赛口接收命令开关（预写 `COMP_FRAME_GATED` 门控宏默认 0）

### 二、检测判据/语义（平台测试件不同）

**6. CT 启停段行为**
- 情况A：平台不查 CT 持续（只看 VIB/SS/频率）→ 默认固件（关源 0.42s 退出）
- 情况B：平台查 CT 持续（夹着必须恒 1）→ `CT_HOLD_ENABLE=1` 开宏固件（T009 任务 B 在做：1Hz 启停 CT 连续 ≥95%）
- 情况C：平台查关源快速退出 → 默认固件（0.42s vs 开宏 1.2s，两版都带现场二选一）

**7. 判据门限（平台振动源特性不同）**
- 情况A：平台件幅值 <400mg 致 CT 不亮 → `CT_FLAT_A_ON_MG` 现场调低（先用 D 命令看 condAmp/ampMg 实测值再定，config.h:滞回 400/300）
- 情况B：平台件频率 <75Hz（低频源 60~70Hz）→ `CT_FLAT_F_ON_HZ` 调低（现 75/63 滞回；F_OFF 下限受 FREQ_LO=60 编译期断言约束，调前先核）
- 情况C：平台件正常（80~180Hz、数百 mg）→ 全默认零改动

**8. 传感器量程**
- 情况A：冲击削顶（clipLimited=1）→ ACCEL_FS ±2g→±4g 重烧
- 情况B：信号弱 → 检查贴装/夹持压力，不动量程
- 情况C：正常 → 零改动

### 三、LED 指示（赛题 §五硬性要求）

**9. 绿灯（GPIO10，"单片机控制闪烁=正常运行"）**
- 情况A：1Hz 心跳正常闪 → **零改动即达标**（output.cpp:719 `(nowMs/500)&1`，恰为每秒一闪）
- 情况B：不亮/极暗（绿灯 VF 2.5~3.6V 上限风险，07-pinout §5）→ 三步预案：①换备件绿灯（清单每色 2 颗用 1 颗）②飞线反接灌电流+R7 换 360Ω ③`LED_ACTIVE_LOW=1` 重烧
- 情况C：亮但被问频率 → 1Hz 满足"闪烁"要求，答辩口径"每秒一次心跳=电路正常运行"

**10. 黄灯（GPIO5，"预留并可控制亮灭"）**
- 情况A：自动联动（本卡改动：CT=1 时 2Hz 闪，CT=0 灭——"接触闪"直观演示）
- 情况B：`y` 命令切常亮（演示"可控制亮"）
- 情况C：`y` 命令切常灭（演示"可控制灭"）——三态循环 AUTO→ON→OFF→AUTO

**11. 红灯（5V 轨常亮=稳压正常）**
- 情况A：常亮正常 → 零固件事
- 情况B：不亮 → 硬件排查：AMS1117 反馈电阻 R1=120Ω/R2=360Ω 焊反（Vout≈1.63V）或 LED 焊接（T004 P0 经验）
- 情况C：闪烁 → 稳压跌落，查 12V 输入与开关触点

### 四、振动源驱动（T009 任务 A 设备侧）

**12. 占空比/默认值**
- 情况A：平台件轻（易起振）→ 默认占空比调低（KEY4 现场调，登记值仅是起点）
- 情况B：平台件重（起振难）→ KEY3 调高；踢一脚已有（0→非0 先 100%/200ms）
- 情况C：完全起不来 → 检查 12V 供电与振子接线

**13. 启停档位**
- 情况A：0~3Hz 内任意档 → 四档 0.5/1/2/3Hz 已覆盖（KEY2 自动模式切档）
- 情况B：平台要求特定频率（如 2.5Hz）→ `CYCLE_TABLE` 一行改（200/200ms）重烧
- 情况C：SS 精度被质疑 → 双重踢修复后四档 SS 实测佐证（T009 任务 A 验收数据）

**14. 供电**
- 情况A：正常 → 不动
- 情况B：BROWNOUT 复位（满压踢时跌）→ 避免弱 USB 口，12V 独立供电或换强口（T009 阶段 2 实测教训）
- 情况C：USB 烧录与 12V 并存 → 烧录时暂拔 12V（防地环路），烧完恢复

### 五、硬件/接线（现场操作）

**15. 共地**（T008 发现：USB-TTL 不共地收 0 字节；比赛 4pin 自带 GND 天然满足）
- 情况A：4pin 对接 → 天然共地，零风险
- 情况B：外接 USB-TTL 调试 → TX=GPIO21/RX=GPIO20 + GND 必接
- 情况C：接反 TX/RX → 收不到数据，对调两根杜邦线即可（无损坏风险，TTL 电平）

**16. I2C 故障**（T004 P0 经验：H3 弯折 3min I2C 错=0 已验）
- 情况A：正常 → 不动
- 情况B：弯折后读失败 → 检查 MPU6050 模块邮票孔焊接（跨弯曲避让区 4 线）
- 情况C：上电即 FAULT → SDA/SCL 焊接检查（GPIO8/9）

**17. 烧录模式**（ESP32-C3 模块）
- 情况A：USB 直插可烧 → 不动
- 情况B：需手动进 boot → 按住 BOOT→按 RESET→松 RESET→松 BOOT（赛题 §九）
- 情况C：CDC 被占 → UART 烧录备用路径（CDCOnBoot=cdc 现状，双 FQBN 编译先例）

## 代码改动项（本卡唯一代码工作，T009 任务 B 完成后执行——共文件 output.cpp 串行）

### 改动 A（必做）：黄灯 CT 接触闪 + `y` 命令三态

- **涉及文件**：仅 `output.cpp`（①`ledUpdate` LED_RUN 分支黄灯逻辑；②调试口命令分发新增 `case 'y'`，与 D 命令同区；③`printStatus` 增黄灯状态行）
- **规格**：①黄灯自动态=CT 联动 2Hz 闪（半周期 250ms `(nowMs/250)&1`），CT=0 灭（接触判定字段以 `Result` 实际字段为准，D 命令 ct 列同名语义；2Hz 与 FAULT 4Hz 频率不同且 FAULT 伴绿灭，不混淆）；②`y` 三态循环 AUTO→ON（常亮）→OFF（常灭）→AUTO，手动态优先于自动联动，printStatus 回显 `[LEDY] AUTO|ON|OFF`；③`LED_FAULT`/`LED_CAL`/绿灯心跳**一律不动**；④不加门控宏（LED 不在数据路径）
- **验收 7 条**：绿灯 1Hz 不变；黄灯 CT 联动实测（夹振动件闪/松手灭，同段 ≥10 帧证 CT 时序）；`y` 三态回显正确；**$VD 帧零变化**（烧录后 ≥300 帧恒 35 字节校验全过）；FAULT/CAL 不变；宿主测试全量回归一致；RT 附 GBK 答辩口径一行

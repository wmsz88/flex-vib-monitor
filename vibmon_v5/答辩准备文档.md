## 1. 一分钟项目概括

本项目面向仿生手柔性感知场景，设计并制作了一块可贴合仿生手指弧面的柔性 PCB 振动检测模块。硬件以 ESP32-C3 为控制核心，通过 I2C 实时读取 MPU6050 六轴数据；软件在 1kHz 采样基础上完成振动主频、启停频率、闭合姿态和接触状态的实时判断，并通过 TTL 串口向外部测试平台输出结果。

核心设计思想是把两类物理量分开：

1. **机械姿态**：用陀螺积分闭合角判断“松手 / 已闭合”；
2. **振动传导**：用加速度交流包络 `A` 和主频 `F` 判断“闭合后是否可靠接触到振动物体”。

这样可以避免把“手指合拢”误当作“夹到物体”，也能在物体不振动时保守输出“无接触证据”，而不是猜测接触状态。

## 2. 硬件设计答辩要点

### 2.1 电源链路

外部输入为组委会提供的 12V 电源，经滑动开关进入 AMS1117-ADJ 线性稳压电路，输出约 5.02V，给 ESP32-C3 模块和 MPU6050 模块供电。

答辩要点：

- 总开关串接在稳压电路前端，断开后整板完全断电，满足“不得存在静态功耗”的要求；
- AMS1117-ADJ 通过 `R1=120Ω / R2=360Ω` 设置约 5V 输出；
- 关键电容包括输入 10µF、ADJ 旁路 10µF、输出 22µF，并在 MPU6050 负载端布置 0.1µF 去耦；
- 红色 LED 硬件直连 5V 常亮，表示稳压输出正常。

### 2.2 控制与传感链路

ESP32-C3 通过硬件 I2C 读取 MPU6050：

| 信号 | ESP32-C3 | MPU6050 | 说明 |
|---|---|---|---|
| SDA | GPIO8 | SDA | 硬件 I2C 默认数据脚 |
| SCL | GPIO9 | SCL | 硬件 I2C 默认时钟脚 |
| 5V | 5V 轨 | VCC | MPU6050 模块工作电压 |
| GND | GND | GND | 公共地 |

选择硬件 I2C 的原因：

- ESP32-C3 的硬件 I2C 默认引脚正好是 GPIO8/GPIO9；
- 1kHz 采样下硬件 I2C 更省 CPU，能保留算力给滤波、频率估计和串口输出；
- 总线上只有 MPU6050 一个器件，结构简单、干扰路径少。

### 2.3 外部串口与供电接口

4pin 标准接口线序采用命题图 3：

| 序号 | 信号 | 说明 |
|---|---|---|
| ① | TX，GPIO21 | 模块发送到测试平台 |
| ② | RX，GPIO20 | 测试平台发送到模块 |
| ③ | GND | 共地 |
| ④ | VIN | 12V 输入 |

现场接线必须反复核对 VIN/GND，不允许反接；上电前应确认正负极。

### 2.4 三灯设计

| LED | 电路 | 含义 |
|---|---|---|
| 红 | 5V 常亮 | 稳压输出正常 |
| 绿 | GPIO10 控制闪烁 | 电路和固件正常运行 |
| 黄 | GPIO5 控制 | 可控预留，当前用于振动/状态提示 |

绿灯风险说明：官方绿色 LED 的正向压降上限可达 3.6V，高于 GPIO 输出 3.3V。本设计保留 `120Ω` 限流电阻，典型压降下约 2.5mA，偏暗但可辨。现场预案是：先换备件 LED；若仍不亮，可改为灌电流接法并同步修改 `LED_ACTIVE_LOW`。

### 2.5 柔性板结构

- 外形按组委会标准框设计，整体不超过 100mm × 25mm；
- 板长分为主体段与窄条段，MPU6050 位于靠近指尖的窄条区，便于贴合振动源；
- 强制弯曲避让区不布置器件，仅允许走线与过孔；
- 跨弯曲区仅布置必要信号：5V、GND、SDA、SCL；
- MPU6050 靠近检测端，使振动路径短、衰减小。

## 3. 软件架构答辩要点

### 3.1 模块划分

```text
config.h     参数与编译期边界检查
mpu.*        MPU6050 初始化、I2C 读写、六轴原始数据
sampler.*    1kHz 定时采样、环形缓冲、掉线与缺口统计
dsp.*        标定、去零偏、高通、包络、主频估计
state.*      振动启停、启停频率、闭合角、接触状态
posture.*    START/HONGEST 静态姿态诊断，不参与正式 contact
output.*     调试串口、比赛帧、LED、打标 CSV
```

### 3.2 采样与标定

- 加速度采样 1kHz；
- 陀螺每 4 个采样周期读取一次，等效 250Hz，积分步长 4ms；
- 上电静置标定约 3.2s，计算加速度零偏、陀螺零偏、噪声底和静置质量；
- 标定采用“候选配置 + 全部校验通过后一次性提交”的事务化设计，失败时沿用上次有效标定或编译期默认参数，不会把坏参数写入运行配置。

### 3.3 振动主频检测

加速度信号先去重力零偏，再经高通滤波，得到三轴交流分量。系统选择能量最大的轴作为主轴，在滑动窗口内通过过零间隔估计持续振动主频。

当前有效频段设置为 60~220Hz，覆盖比赛要求的 80~180Hz。

### 3.4 启停频率检测

启停频率不是直接对 0~3Hz 低频信号采样，而是先由振动包络得到“有振动 / 无振动”状态，再记录“停→振”边沿时间，计算状态切换周期。

实测结果：

| 设定 | 固件读数 | 结果 |
|---:|---:|:--:|
| 0.5Hz | 0.50Hz | 通过 |
| 1Hz | 1.00Hz | 通过 |
| 2Hz | 2.00Hz | 通过 |
| 3Hz | 2.94Hz | 通过 |

### 3.5 闭合角与接触判据

陀螺积分得到闭合角 `theta`，用于判断机械手是否合拢：

```text
theta < 45°   -> 松手
theta > 60°   -> 已闭合
```

接触判定采用三重与：

```text
已闭合
且 幅值 A > 400mg
且 主频 F > 75Hz
=> contact = 1
```

退出使用滞回阈值，幅值低于 300mg 或主频低于 63Hz 后释放。

### 3.6 为什么不用姿态单独判断夹物

实验发现：

- 空握闭合角约 106~111°；
- 夹 4cm 物体闭合角约 100°；
- 二者只差 6~11°，跨位置变化会淹没这个差异；
- 三轴 Y/Z 偏移虽然方向稳定，但夹物组内标准差较大，不能作为可靠判据。

因此当前设计明确：闭合角只负责判断“手指是否合拢”，是否夹到振动物体必须由振动传导证据 `A/F` 判断。

### 3.7 静态物体接触的边界

如果物体完全不振，仅靠 MPU6050 无法可靠证明接触。这是物理边界，不是简单算法问题。

当前固件不会把“闭合但无振动”误称为接触，而是输出：

```text
closed=1, ct=0
```

含义是“机械手已闭合，但没有足够振动证据证明接触”。

### 4.3 当前阻塞

5 轮重复性测试尚未通过。真实机械动作中 MPU6050 曾出现：

```text
[FAULT] 传感器无响应
[MPU] 初始化失败：无应答 (寄存器 0x75)
```

这属于 I2C 物理连接间歇性问题，当前优先怀疑排线、焊点、接插件或应力集中，而不是固件算法。恢复测试前必须先保证：

```text
静止 30s：I2C错=0、读失败=0、不连续=0
动态弯折 30s：仍为 0，且无 [FAULT]
```

## 5. 常见答辩问题与回答

### Q1：为什么用陀螺仪？加速度不是已经能测振动吗？

加速度适合测振动，但姿态变化与振动都会影响它；陀螺可以直接测角速度，与重力方向无关。用陀螺积分闭合角，可以更稳定地判断“手指是否合拢”。两者互补：陀螺判断闭合姿态，加速度判断振动接触。

### Q2：陀螺积分会不会漂移？

会，这是惯性器件固有特性。固件做了三层处理：

1. 标定陀螺零偏；
2. 小角速度死区内不积分；
3. 回到张开位且静止满一定时间后清零。

实测静置 10s，闭合角保持 0°，没有明显漂移。

### Q3：为什么不用神经网络或加权模型判断接触？

现有数据规模不足以训练可靠模型，而且比赛现场部署复杂，出了问题也难定位。我们用三条可解释的判据取交集：姿态（陀螺积分闭合角）、幅值、主频。其中幅值是最稳的一条——空夹中位只有 6mg、最坏瞬态 304mg，真接触在 500~1152mg，两侧各有 1.3 倍以上余量，门限取 400mg。主频作为第二条证据：真接触稳定在 158~179Hz；空夹有时会因机械共振测出 86~169Hz 的假频，所以主频不单独作判据，只用来在幅值被削顶时兜底。这样判据既能解释清楚每一条为什么成立，也留了明确的失效边界。

### Q4：为什么静止接触不输出 contact=1？

静止物体没有振动传导证据。仅靠姿态无法区分空握与夹物，我们宁可输出“闭合但无接触证据”，也不猜测。这是保守设计，避免误报。

### Q5：如果现场 I2C 掉线怎么办？

固件会进入故障恢复流程，重新初始化 MPU6050，并清空当前有效结果。调试输出中 `I2C错`、`读失败`、`不连续` 会实时暴露问题。比赛前必须检查 SDA/SCL/电源/GND 和排线应力点，保证动态弯折时统计为 0。

### Q6：绿灯偏暗怎么办？

绿色 LED 正向压降上限较高，GPIO 3.3V 驱动时电流可能偏小。现场先换备件 LED；若仍偏暗，可改为灌电流接法并同步修改 `LED_ACTIVE_LOW` 宏。

## 6. 现场陈述建议

答辩时建议按以下顺序讲：

1. **需求**：检测仿生手接触状态、80~180Hz 持续振动、0~3Hz 启停频率；
2. **硬件**：12V→5V 电源、ESP32-C3 + MPU6050、柔性板结构、4pin 串口；
3. **软件链路**：采样→标定→滤波→主频→启停→闭合角→接触判定；
4. **验证**：双构建 0 warning，主机测试通过，实板功能验证通过；
5. **工程边界**：静止接触物理上难证，I2C 可靠性需现场重点保障；
6. **结论**：代码作为候选版本可备赛，硬件连接修复后继续做重复性验收。

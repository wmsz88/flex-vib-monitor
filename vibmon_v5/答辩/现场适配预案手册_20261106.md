# 现场适配预案手册

> 2026-11-06 · flash (EXEC) 按 T010 任务卡誊清核对
> **本手册对应「现场适配版」= `代码\vibmon_v7\`**（= v6 接触三条 + 黄灯接触闪 / `y` 命令 + 三只预案宏）
> `代码\vibmon_v6\` 是 T013 上板验收过的那一版，**保持原样归档，不要再改它**；所有现场改动都落在 v7

## 1. 现场决策两行表（照现象换固件）

| 现场现象 | 换哪版 | 一句话 |
|---|---|---|
| 平台按 35 字节 `$VD` 读 | **def** | 出发版，不动 |
| 平台要"接触/闭合"多一个字段 | **cl** | 37 字节，CT 后插 CL |
| 平台只认 CSV 文本行 | **csv** | `ct,vib,freq,amp,ss` |
| 平台嫌 50Hz 太快/丢帧 | **div2** | 降到 25Hz（SEQ 仍连续） |
| 平台要求"发指令才发数据" | **gate** | 比赛口收 `S` 开、`X` 停 |
| 平台要求"不振动就立刻掉 CT" | **v5sem** | 回退关源 0.3~0.42s 退出语义 |
| USB-CDC 口被占 / 要 UART 口调试 | **uart** | 非 CDC 构建 |

**烧录一条命令**（COM 换成实际口）：

```bash
arduino-cli upload -p COMx --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc --input-dir "<变体目录>"
```

变体目录见下一节；`uart` 变体把 FQBN 里的 `:CDCOnBoot=cdc` 去掉。

## 3. 十七项预案

### 一、串口/帧协议

**1. 帧格式** 【零改动 / 一行宏重烧】

- **情况A 平台直接读我们的帧** → 零改动。`$VD` 35 字节纯 ASCII；T008 实板 3008/3008 校验错 0，T013 复测 3102 帧全部 35 字节、抽检 CHK 5/5 对。
- **情况B 平台要"接触/闭合"字段** → 烧 `cl` 变体（37 字节）。改法：`代码\vibmon_v7\config.h` 的 `COMP_FRAME_CL` 由 `0` 改 `1`，一行，重烧。
- **情况C 平台只认 CSV 文本行** → 烧 `csv` 变体。改法：同文件 `COMP_FRAME_CSV` 由 `0` 改 `1`（已预写，默认关，出发版逐字节不变）。输出形如 `1,1,157.8,755,0.00`。平台的列序不同 → 改 `代码\vibmon_v7\output.cpp` 里 `compBuildFrame()` 里那一条 `snprintf(out, ..., "%u,%u,%.1f,%u,%.2f\r\n", ...)` 的格式串，约 1 行。
- **验证**：串口工具切十六进制，数一帧字节数（35 / 37）或看有没有 `$VD,` 前缀。

**2. 波特率** 【零改动 / 一行宏重烧】

- **情况A 平台 115200** → 零改动。
- **情况B 平台要 9600/4800** → 改 `config.h` 的 `COMP_BAUD`（现 `115200`）为 `9600` 或 `4800`，一行，重烧。调试口 `BAUD` 不受影响。
- **情况C 平台可配置** → 零改动，现场调平台侧。
- **验证**：换波特率后 `$VD` 帧应恢复可读；收不到就是波特率没对上。

**3. 帧率** 【零改动 / 一行宏重烧】

- **情况A 50Hz 可接受** → 零改动。
- **情况B 平台处理不过来/丢帧** → 烧 `div2`（25Hz），或改 `config.h` 的 `COMP_FRAME_DIV`：`2` = 25Hz、`5` = 10Hz。只降发送频率，`SEQ` 仍逐帧连续，平台按 SEQ 判丢帧不会误报。
- **情况C 平台要更快** → 做不到并如实说明：判据刷新受 DSP 包络窗约束，50Hz 已是设计值；提高只会发重复值。
- **验证**：数 1 秒内的帧数（50 / 25 / 10）。

**4. 编码** 【零改动】

- **情况A 平台是 GBK 环境** → 零改动。`$VD` 帧只有字母、数字、逗号、hex，任何编码都能直接解析 —— **答辩标准口径**。
- **情况B 串口工具显示乱码** → 切十六进制模式核对字节；是工具显示问题，不是帧问题。
- **情况C 平台要求中文应答** → 不做。历届六年无此要求；若评委坚持，用调试口 `D` 命令输出文本行现场应对。

**5. 发送使能/触发** 【零改动 / 一行宏重烧】

- **情况A 接上就发** → 零改动（出发版现状）。
- **情况B 要比赛口完全静默**（接错口、调试期）→ 改 `config.h` 的 `COMP_FRAME_ENABLED` 由 `1` 改 `0`，整个发送函数编译为空，零开销。
- **情况C 平台命令触发式** → 烧 `gate` 变体，或改 `COMP_FRAME_GATED` 由 `0` 改 `1`。比赛口收 `S` 开始发、收 `X` 停止；上电默认静默。
- **验证**：静默版接上后一个字节都不出；`gate` 版发 `S` 后立刻出帧。

### 二、检测判据/语义

**6. CT 启停段行为** 【零改动 / 一行宏重烧】

- **情况A 平台只看 VIB/SS/频率，不查 CT 持续** → 零改动（出发版 v6）。
- **情况B 平台查 CT 持续（夹着必须恒 1）** → 零改动即满足：v6 只要手保持姿态，**振源关掉也保持 CT=1**（T013 实测关源后 16.4s 仍为 1）。
- **情况C 平台要求"不振动/松手就快速掉 0"** → 烧 `v5sem` 变体，或改 `config.h` 的 `CT_V6_ENABLE` 由 `1` 改 `0`（回到 v5 语义：关源 0.30~0.42s 退出）。
- **验证**：夹住→开振源→关振源，看 `ct` 是保持 1（v6）还是数百毫秒内掉 0（v5sem）。

**7. 判据门限（平台测试件不同）** 【一行宏重烧】

- **情况A 平台件幅值小、CT 不亮** → 先用调试口 `D` 命令看实测 `ampMg`，再把 `config.h` 的 `CT_FLAT_A_ON_MG/CT_FLAT_A_OFF_MG`（现 `400/300`）调低，保持 OFF 比 ON 小 25% 左右。
- **情况B 平台件频率偏低（60~70Hz）** → 调 `CT_FLAT_F_ON_HZ/CT_FLAT_F_OFF_HZ`（现 `75/63`）：`OFF` 不能低于 `FREQ_LO`（60Hz，编译期断言会拦住）。
- **情况C 平台件正常（80~180Hz、数百 mg）** → 零改动。
- **验证**：`D` 命令三列 `condPosture/condAmp/condFreq` 应随夹持变化；调门限后 `ct` 跟着翻转。

**8. 传感器量程** 【硬件操作 / 一行宏重烧】

- **情况A 冲击削顶（`#V6` 里 `clip` 计数涨、帧 `[clip]`）** → 改 `config.h` 的 `ACCEL_FS_SEL` 由 `1`（±4g）改 `2`（±8g）重烧。
- **情况B 信号弱** → 检查贴装与夹持压力，**不动量程**（放大只会连噪声一起放大）。
- **情况C 正常** → 零改动。

### 三、LED 指示（赛题硬性要求）

**9. 绿灯（GPIO10，"单片机控制闪烁 = 正常运行"）** 【零改动 / 硬件操作】

- **情况A 1Hz 心跳正常闪** → 零改动即达标（`output.cpp` 里 `(nowMs / 500) & 1`，每秒一闪）。
- **情况B 不亮或极暗**（绿灯 VF 2.5~3.6V，接近 3.3V 上限）→ ① 换备件绿灯；② 飞线改灌电流接法、R7 由 120Ω 换 360Ω；③ 改 `config.h` 的 `LED_ACTIVE_LOW` 由 `0` 改 `1` 重烧。
- **情况C 被问闪烁频率** → 答"1Hz 心跳 = 电路正常运行"，已满足"闪烁"要求。

**10. 黄灯（GPIO5，"预留并可控制亮灭"）** 【零改动 / 命令】

- **情况A 演示"跟着接触闪"** → 零改动。出发版黄灯默认 AUTO：CT=1 时 2Hz 闪、CT=0 灭。
- **情况B 演示"可控制亮"** → 调试口发 `y`，黄灯切常亮（回显 `[LEDY] ON`）。
- **情况C 演示"可控制灭"** → 再发 `y`，黄灯切常灭（回显 `[LEDY] OFF`）；第三次 `y` 回 AUTO。三态循环 AUTO→ON→OFF→AUTO。
- **验证**：`S` 命令的状态行里有 `黄灯 [LEDY] AUTO|ON|OFF`。故障时黄灯是 4Hz 快闪且绿灯灭，与上面的 2Hz 接触闪、常亮、常灭都不同。

**11. 红灯（5V 轨常亮 = 稳压正常）** 【硬件操作】

- **情况A 常亮** → 正常，固件不管。
- **情况B 不亮** → 查 AMS1117 反馈电阻（R1=120Ω / R2=360Ω 焊反会让 Vout≈1.63V）或 LED 焊接。
- **情况C 闪烁** → 稳压跌落，查 12V 输入与开关触点。

### 四、振动源驱动（设备侧）

**12. 占空比** 【现场按键 / 一行宏重烧】

- **情况A 平台件轻、易起振** → 振源板 KEY4 逐次 −5% 调低，现场记下合适值。
- **情况B 平台件重、起不来** → KEY3 +5% 调高；起振已带"0→非 0 先 100%/200ms 踢一脚"。
- **情况C 完全起不来** → 查 12V 供电与振子接线（不是固件）。
- **换默认值**：改 `Desktop\STM32project\vibsource_c3_key\config.h` 的 `DUTY_DEFAULT_A`（新振子）／`DUTY_DEFAULT_B`（旧振子）重烧。

**13. 启停档位** 【零改动 / 一行宏重烧】

- **情况A 0~3Hz 内任意档** → 零改动：四档 0.5/1/2/3Hz（振源串口 `T0`~`T3`，或 KEY2 在自动模式循环切档）。
- **情况B 平台要特定频率（如 2.5Hz）** → 改振源 `config.h` 的 `CYCLE_TABLE` 一行（ON/OFF 毫秒）重烧。
- **情况C 被质疑启停精度** → 报 T009/T013 实测：旧振子 2Hz 段 `SS` 中位 1.99Hz、3Hz 段 2.93~2.95Hz。

**14. 供电** 【硬件操作】

- **情况A 正常** → 不动。
- **情况B BROWNOUT 复位（电机一启动就跌）** → 判定方法：**振源板的串口在系统里消失几秒又回来**（USB 重枚举）= 板子复位了；此时 `q` 状态里的 `out 90%` 仍是寄存器值，但电机没转，检测模块只读到 `A≈6mg` 的噪声。处置：别用弱 USB 口 / hub / 延长线，直插机箱后置口；检测板与振源板分开供电；有独立 12V 就给振子单独供。
- **情况C USB 烧录与 12V 同时接** → 烧录时暂拔 12V（防地环路），烧完恢复。

### 五、硬件/接线

**15. 共地** 【硬件操作】

- **情况A 用比赛 4pin 对接** → 天然共地（4pin 自带 GND），零风险。
- **情况B 外接 USB-TTL 调试** → TX=GPIO21、RX=GPIO20，**GND 必须接**；不共地会一个字节都收不到（T008 踩过）。
- **情况C 接反 TX/RX** → 收不到数据，把两根杜邦线对调即可，TTL 电平无损坏风险。

**16. I2C 故障** 【硬件操作】

- **情况A 正常** → 不动。
- **情况B 弯折后读失败** → 查 MPU6050 模块邮票孔焊接（跨 15.2mm 弯曲避让区的 4 根线）。
- **情况C 上电即 FAULT**（`[MPU] 初始化失败：无应答`）→ 查 SDA/SCL 焊接与 GPIO8/9 电平。

**17. 烧录模式** 【硬件操作】

- **情况A USB 直插可烧** → 不动（本机实测 `arduino-cli upload` 直接成功）。
- **情况B 需手动进 boot** → 按住 BOOT → 点一下 RESET → 松 RESET → 松 BOOT。
- **情况C CDC 口被占/识别不到** → 换 `uart` 变体（非 CDC 构建）走 UART 烧录口。

## 4. 串口命令速查（调试口，USB-CDC）

## 5. 一句话答辩口径（编码问题）

> "比赛帧 `$VD,` 开头，35 字节纯 ASCII（字母、数字、逗号、两位十六进制校验），不含任何多字节字符，GBK/UTF-8 环境都能直接解析；平台上显示异常时切十六进制核对字节即可。"

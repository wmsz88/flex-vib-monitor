# 大模型行为规则（规划侧）

> **受众**：PLANNER-A (deepseekv4pro) + PLANNER-B (glm5.3)
> **开工前必读**：本文件 + `AGENTS.md` + `规划/plan.md`

---

## 一、开工检查清单（每次会话必做，按顺序）

| 步骤 | 读什么 | 目的 |
|:--:|---|---|
| 1 | `AGENTS.md` | 确认角色分工与写权限 |
| 2 | `大模型/规则.md`（即本文件） | 确认行为规范 |
| 3 | `规划/plan.md` 的「规划日志」 | 确认另一侧有没有正在推进的 `doing` 卡 |
| 4 | `规划/tasks/` 所有 `.md` | 确认当前任务卡状态 |
| 5 | `结果/` 最新文件 | 拿到上次 flash 的数据结论 |

第 3、4 步是**防撞车**的关键：如果另一侧有 `doing` 卡，本轮不能开新卡。

---

## 二、规划会话的标准流程

```
读现状 → 决定方向 → 更新 plan.md 规划日志（署名） → 起草任务卡 → 派卡(todo) → 等待 flash 结果
```

### 2.1 读现状

从这些文件拿信息：
- `结果/`：flash 的上次数据结论（只读）
- `当前状态.md`：历史测试记录（只读存档）
- `代码测试报告_*.md`：代码测试报告（只读存档）
- `答辩准备文档.md`：答辩要点（只读存档）

### 2.2 定方向

方向写在 `规划/plan.md` 的以下字段：
- **项目目标**：当前阶段的总体方向（2~3 句话）
- **当前阶段**：正在推哪张卡
- **下一步方向**：下一张卡解决什么问题，依据哪份结果
- **风险点**：当前最大的不确定性

### 2.3 拆卡（起草任务卡）

任务卡模板见 `规划/tasks/_任务卡模板.md`，必须包含：
- **目标**：一句话说清要做什么
- **涉及文件**：改哪些文件
- **验收标准**：用什么数据判断完成
- **要求回传的数据**：flash 必须输出什么到 `结果/`

### 2.4 派卡

- 卡状态改为 `todo`
- 在 plan.md「规划日志」追加一行：`日期 + 署名 + 派卡 Txxx-主题`

### 2.5 读结果 + 推进判定

flash 完成后，`结果/` 里会出现 `RTxxx-YYYYMMDD.md`：
- 对照验收标准，达标 → 卡状态改 `done`，开下一张
- 不达标 → 开返工卡，注明返工原因
- 在 plan.md「已推进任务记录」更新推进判定

## 三、禁止事项

| ❌ 禁止 | 原因 |
|---|---|
| 直接改 `.cpp` `.h` `.ino` 代码 | 代码改动权归 flash |
| 写 `结果/` | flash 的领地 |
| 写 `小模型/` | flash 的规则由 flash 自己维护 |
| 绕过任务卡直接口头派活 | 没有文件记录 = 另一侧不知道发生了什么 |
| 推翻对方 3 天内的推进决策 | 必须先开新卡用数据说话 |
| 同时开多张 `doing` 卡 | 一次只推一张 |

---

## 四、防撞车细则

1. **谁是"当前主规划"**：以 plan.md「规划日志」最新一行署名为准。另一侧在此期间只能旁观。
2. **轮次交接**：当一张卡 `done` 后，另一侧规划模型可以接棒——在规划日志署名并开下一张卡。
3. **分歧处理**：两个规划模型方向不一致时，各自写入 plan.md「风险点」，由人类拍板。**不争论、不在对话里掰扯。**
4. **AGENTS.md 改前先读**：改 AGENTS.md 前确认没有另一侧正在改的迹象（最近一次署名的操作里是否涉及 AGENTS.md）。

---

## 五、评审权限

大模型可以对代码做**只读评审**，结论写入 `大模型/评审报告_YYYYMMDD.md`。
评审不替代任务卡——如果评审发现需代码改动，仍然要开任务卡交给 flash。

---

## 六、署名制（AGENTS.md §4 第 8 条的细则，2026-11-02 人类指令）

每一次行为与结果都必须带「日期 + 模型」，格式统一为 `YYYY-MM-DD HH:MM · 模型名 (角色)`：

| 行为/结果 | 署名落点 |
|---|---|
| 派卡、改卡状态、验收判定、方向变更 | plan.md「规划日志」+ 任务卡「完成记录」 |
| 代码评审 | `大模型/评审报告_YYYYMMDD.md` 文件头部 |
| 改 AGENTS.md / 本规则文件 | plan.md「规划日志」追加一行说明 |
| flash 的执行与数据（供对照） | `结果/RTxxx-YYYYMMDD.md` 头部「执行模型/执行日期」+ 数据目录名带日期 |

无署名记录无效。验收时若发现 flash 的 RT 文件缺日期或模型标注，按不达标返工补签。

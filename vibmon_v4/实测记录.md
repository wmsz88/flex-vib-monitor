## 1. 装贴条件

### 1.1 姿态定义（每次测量必须复现）

| 项 | 规定 |
|---|---|
| 手指 | **中指**（其余手指自然舒展，不借力压模块） |
| 模块位置 | **指甲盖正上方**，敏感元件（MPU6050）投影落在甲板中心 |
| 手的朝向 | **手指背放** —— 手背朝上、指甲朝上，中指平放于桌面或悬空静止 |
| 固定方式 | 胶带/绑带只压模块板体，**不遮指示灯**，不压住指甲边缘影响振动传导 |
| 排线 | 4PIN 杜邦线自然引出，不与桌面摩擦（避免摩擦噪声进包络） |

> **为什么要把姿态写死**：`CT_MODE=3` 的判据是「当前姿态到基准姿态的距离」。
> 基准是一次采集得来的，姿态不可复现就等于每次换基准，阈值全部作废。

### 1.2 基准采集时机（这条最容易做错）

`CT_MODE=3` 的参考点名字叫「平放基准」，但在本装贴方式下它的真实含义是
**「中指指甲盖 + 手指背放 + 静止」这个零点姿态**，不是"放在桌面上"。

固件上电后的自动流程是：

```
上电 -> dspCalibrate() 自动标定 3.2s（CAL_BIAS_MS 2000 + CAL_NOISE_MS 1200）
     -> stateApplyCal()          —— 这一步会清掉参考点
     -> stateTickFlatRef() 自动采集基准 0.8s（SETTLE 300ms + AVG 500ms）
```

所以**必须按这个顺序操作**：

1. 先把模块贴到中指指甲盖、摆成手指背放；
2. **再**上电/复位；
3. 全程 3.2s + 0.8s **不要动**（含绿灯+黄灯常亮的标定阶段）。

**反例（会静默出错）**：先在桌面上电（采到桌面姿态作零点），再贴到手指上。
此时重力分量在传感器坐标系里的变化会被当成「姿态偏离」，
`flatDist` 可能一上来就超过占位阈值 `CT_FLAT_D_ON_MG = 400mg`，
`contact` 直接判 1 —— **看起来"接触识别很灵敏"，其实是零点错了**。

> 历史实测佐证：v3 的 `CT_MODE=2` 数据里，"松开"态到参考点的距离是 **1082~1750mg**。
> 这个量级说明指关节旋转引起的重力分量变化远大于 400mg，
> 一次装贴姿势错误就足以吃掉整个判据余量。

### 1.3 采到基准的判据（每次开机都要确认）

串口发 `S`，看接触那一行：

| 输出 | 含义 | 处置 |
|---|---|---|
| `接触 0(可信)  平放到 3 mg …` | 基准已采到，可开始测量 | 继续 |
| `接触 采集中… 请让设备保持平放不动` | 正在自动采集 | 等 0.8s |
| `（自动采集 3 次均判定为在动，极差 X>60 mg；请放稳后按 't' 重采）` | 采集失败，**`contactValid=false`** | 停手 -> 按 `t` -> 等 0.8s |
| `接触 0(不可信)  未采到平放基准` | 未采集或已清除 | 按 `t` |

> `CT_REF_AUTO_RETRY = 3` 用尽后不会无限重试。
> 手指悬空静止比桌面静止更容易被 `CT_REF_MAX_SWING_MG = 60mg` 判成"在动"
> —— **建议手指背放时让中指自然搭在桌面上**，而不是悬空。
> 若确实需要悬空测量，先记录这一现象，再决定是否放宽该宏（放宽后要重新验 §5.1）。

### 1.4 重新标定 / 换姿态的连带后果

`stateApplyCal()` 会清掉基准。因此：

- 发过 `c`（重标定）-> **必须**让模块回到 §1.1 姿态，再按 `t` 重采基准；
- 换人 / 换手指 / 换绑带松紧导致甲板朝向变了 -> 同上，按 `t0` 再按 `t`；
- 断线恢复（黄灯 4Hz 快闪后恢复）**不需要**重采：基准跨 `stateReset()` 保留。

## 2. 模块上报的振动数据

**本表说明"能拿到什么数据"，不是实测结果。** 实测数值在 §5。

### 2.1 三个可用数据源

| 数据源 | 命令 | 速率 | 用途 |
|---|---|:--:|---|
| `#SWEEP` 行 | `w`（按需打印） | 手动 | **主频 / 幅值 / 到基准距离 + 有效性标记**，阈值采样用它 |
| 绘图组 1 | `1` | 50Hz | `Freq_Hz`、`Amp_mg`、`SS_Hz_x10`、`Vib_x50`、`Contact_x100`，串口绘图器看趋势 |
| 绘图组 4 | `4` | 1kHz 抽取 | 高通后 X/Y/Z 三轴波形，看谐波与削顶（**需 USB CDC**） |
| 打标 CSV | `k0`~`k6` / `K` | 100Hz | 三轴低通值 + `ctDev` + `ampMg` + 状态，看时序与判定翻转过程 |
| `S` 状态汇总 | `S` | 单次 | 结果 + 各项计数 + 标定参数（含 `平放到 … mg`） |
| `T` 时序统计 | `T` | 单次 | 读耗时 / 样本间隔 / 主循环 / 缓冲水位，验采样健康度 |

### 2.2 `#SWEEP` 字段（阈值采样的主数据源）

```
#SWEEP t=12s F=  129.7Hz A=   41.3mg D=     3mg tr=   12mg vib=1 ct=0 grip=1 cliplim=0 ax=2 ok=1
```

| 字段 | 来源 | 单位 | 无效时 |
|---|---|---|---|
| `F` | `Result.freqHz` — 滞回过零 + 线性插值 + 周期中位数 | Hz | `?` |
| `A` | `Result.ampMg` — 三轴合成 30ms RMS 包络 | mg | `?` |
| `D` | `Result.flatDist` — **到基准姿态的距离**（`CT_MODE=3` 第 1 路） | mg | `?`（未采基准） |
| `tr` | `Result.flatRefSwing` — 采基准时窗口内最大单轴极差 | mg | `?` |
| `vib` | `Result.vib` — 启停双阈值 + 3 次确认 | 0/1 | — |
| `ct` | `Result.contact` — 三重与 + 100ms 确认 | 0/1 | — |
| `grip` | `Result.gripNoObject` — 姿态门过 + 幅值可信 + 频率门未过（**空夹诊断**） | 0/1 | — |
| `cliplim` | `Result.freqClipLimited` — 主频因削顶被降级 | 0/1 | — |
| `ax` | `Result.axis` — 本窗主频取用的轴 0=X 1=Y 2=Z | — | — |
| `ok` | `F` 与 `A` 都有效且未降级 | 0/1 | — |

> **`?` 与 `0` 的区别是这套固件的关键设计**：`?` = 没测出来，`0` = 测出来是 0。
> 写数据表时**不能把 `?` 抄成 0**，否则启停/漏检会被统计成"读数为 0Hz"。

### 2.3 量程与削顶线

| 项 | 当前值 | 依据 |
|---|---|---|
| 加速度量程 | **±4g**（`ACCEL_FS_SEL=1`） | `config.h:49` |
| 削顶判定 | `abs(raw) > 32700`，±4g 下 **≈4000mg** | `ACCEL_CLIP_RAW` |
| 加速度带宽 | 260Hz（`DLPF_CFG=0`） | 保住 180Hz |
| 采样 | 1000Hz，I2C 200kHz，只读 6 字节加速度 | `FS_HZ` / `I2C_CLOCK` |
| 时钟源 | 内部 8MHz（`MPU_CLKSEL=0`） | 若 §5.5 抖动偏大改 1 = PLL |

±4g 下 4000mg 的削顶线离指甲盖传导的微振动幅度很远，**预期不削顶**；
`cliplim` 若持续为 1，优先怀疑量程或机械撞击，而不是算法。

### 2.4 能力边界（写对外结论时照这个措辞）

| 项目 | 赛题要求 | 内部可测带 | 硬边界 |
|---|---|---|---|
| 持续振动 | 80~180 Hz | 60~220 Hz | `FREQ_LO_HZ` / `FREQ_HI_HZ` |
| 启停频率 | 0~3 Hz | 0.1~5 Hz | `SS_T_MAX_MS=12000`，最低 0.083Hz |

- 持续振动与完全静止都**不报启停频率**（`ssValid=false`），不是"测得 0Hz"。
- 220Hz 以上不保证：周期过滤在边界处会泄漏，可能给出偏离 >1.5Hz 的截断读数。
- **±2Hz、0.5s 是本组工程目标，不是官方公布的考核标准。**
- 对外只承诺 80~180Hz / ±2Hz。

### 3.3 `ct_test` 的 6 项失败：是测试过期，不是固件回归

失败项：`T10a 阶跃到接触态后 contact=1`、`T10b 缓慢过渡`、`T10c 进入接触态`、
`T10c 滞回带内(64.0)仍 contact=1`、`T10f 缺口打断后重新累计确认`、`T10g 已确认接触`。

根因：`ct_test.cpp` 的激励只喂**姿态**（默认 `step(devMg, vibAmpMg=0)`），
而 `CT_MODE=3` 要求 `姿态 && 幅值 && 频率` 三路全真才进接触
（`state.cpp combineContact`，进入需三路全真）。测试断言的是 v3 模式 2 的语义。

**旁证（说明不是逻辑坏了）**：

```powershell
g++ -std=c++17 -w -DCT_MODE=2 -I test -I $v4 test/ct_test.cpp "$v4\dsp.cpp" "$v4\state.cpp" -o ct2.exe
./ct2.exe   # -> 全部通过（39/39 项通过，0 项失败）
```

按模式 2 编译就全过，说明状态机与确认链本身工作正常。
但**结论不能反过来**：`ct_test` **没有覆盖模式 3 的幅值门与频率门**，
也就是"空夹判 0、真接触判 1"这条 v4 的核心命题**至今没有任何测试证据** ——
这正是 §4~§5 实板数据要回答的问题。

### 4.2 采集工具

`_probe/capture_measure.py`（本次新增，纯 PC 侧，**不改固件**）：

```powershell
python -X utf8 _probe\capture_measure.py --list
python -X utf8 _probe\capture_measure.py --port COM5 --mode sweep `
    --steps 0:60,4:60,6:60,3:30 --out data\run01
```

| 参数 | 作用 |
|---|---|
| `--mode sweep` | 每秒发 `w`，收 `#SWEEP` 行 -> **采阈值用这个** |
| `--mode label` | 发 `k0~k6` 进打标模式，收 100Hz CSV -> **看时序 / 判定翻转过程用这个** |
| `--steps` | `状态:秒数` 逗号分隔，状态号沿用固件 k0~k6 |
| `--rate` | sweep 发 `w` 的间隔，默认 1s |
| `--settle` | 开串口后的静默等待，默认 8s（标定 3.2s + 基准 0.8s + 余量） |
| `--out` | 输出前缀，生成 `<out>.csv`（解析后）+ `<out>.raw.txt`（原始行取证） |

采完自动按状态分组给 `min / median / max`，并按"取两态之间"原则打印
`CT_FLAT_D / A / F` 建议值与两态余量。**建议值仅供参考，填进 `config.h` 前人工复核。**

> `F` / `A` 无效时脚本在 CSV 里**留空**而不是写 0，与固件的 `?` 语义一致。
> `label` 模式的 CSV **没有 `freqHz` / `flatDist`**，别拿它采阈值。

## 6. 阈值填写规则

采完 §5.1 后按此填 `config.h:224~249`：

```
CT_FLAT_D_ON_MG  = ①上限 + (②下限 - ①上限) * 0.75    // 占位 400
CT_FLAT_D_OFF_MG = CT_FLAT_D_ON_MG * 0.7              // 占位 280
CT_FLAT_F_ON_HZ  = ②上限 + (③下限 - ②上限) * 0.75    // 占位 120  <- 最关键
CT_FLAT_F_OFF_HZ = CT_FLAT_F_ON_HZ * 0.75             // 占位 90
CT_FLAT_A_ON_MG  = "握住静止"与"正常抖动"之间          // 占位 30，仅排除静止
CT_FLAT_A_OFF_MG = CT_FLAT_A_ON_MG * 0.67             // 占位 20
```

**四条硬约束**（`config.h` 末尾有编译期检查，违反直接编译报错）：

| 约束 | 违反后果 |
|---|---|
| 三组都要 `OFF < ON` | 滞回带反了，接触在阈值处反复抖动 |
| `CT_FLAT_F_ON_HZ <= 220` | 高于 `FREQ_HI_HZ` 则接触永远不可能成立 |
| `CT_FLAT_F_OFF_HZ >= 60` | 低于 `FREQ_LO_HZ` 则空夹时主频被下限钉住，退出条件永不满足 |
| `*_INT` 整数副本要与浮点原值同步改 | 编译期检查用的是 `_INT` 版本，只改浮点会绕过校验 |

填完做两件事：

1. 重跑 §5.1，确认 ②（握紧无接触 + 振动）判 `ct=0 且 grip=1`、③（真接触）判 `ct=1`
   —— **注意：主机探针显示按当前判据这两条同时成立做不到**（② 会误报 `ct=1`，
   静止的 ③ 会漏报 `ct=0`）。若实测复现，必须先走 `进度.md` §4.2 改结构，不能只调阈值。
2. 两个 FQBN 都编译一遍（`esp32c3` 与 `esp32c3:CDCOnBoot=cdc`）。

## 7. 已知风险与待观察

| # | 风险 | 为什么会出问题 | 怎么验 |
|:--:|---|---|---|
| 1 | **基准姿态 ≠ 测量姿态** | 在桌面上电采了桌面零点，再贴到手指（§1.2 反例） | §5.6 重复性表 |
| 2 | **悬空静止采不到基准** | `CT_REF_MAX_SWING_MG=60` 对手抖敏感，重试 3 次就放弃 | 看 `S` 是否报"3 次均判定为在动" |
| 3 | **频率门分不开空夹** | v4 假设"空夹没有物体共振所以频率上不去"；若皮肤/指甲/指骨本身把激励传成结构共振，② 的 `F` 会和 ③ 一样高 | §5.1 第 2 条，**最可能推翻设计的一条** |
| 4 | **接触靠关节旋转而非压力** | v3 实测过：轻触不转测不到。模块在指甲（远节指骨），DIP 关节转角直接改重力分量 —— 对本装贴方式是好事，但意味着"压得重但完全不动"测不出来 | §5.1 状态 ② 里补一次"压住但绝不转指"的采样 |
| 5 | **`ax` 取用轴在态间切换** | 主频自动选交流能量最大的轴；换激励方向或换绑带松紧，主轴可能从 Y 跳到 Z | §5.2 的 `ax` 列 |
| 6 | **USB CDC 未复验** | 绘图组 4（三轴波形）只能在 CDC 模式看；非 CDC 下 `Serial` 走 GPIO21/20 | §3.1 补一次 `CDCOnBoot=cdc` |
| 7 | **比赛口静默** | `COMP_FRAME_ENABLED=0`，4PIN 上**一个字节都不发**，现场联调前必须先定帧口径 | §3.5 第 6 条 |
| 8 | **禁止 Wi-Fi/BLE** | AMS1117 压差 7V、Pd≈0.4W，射频峰值 300mA 会热关断 | 代码里无任何 `WiFi`/`BLE` 调用，改代码时别引入 |

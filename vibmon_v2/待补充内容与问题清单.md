## 1. 总体判断

第二版的数据链路与预期架构基本一致：

```text
硬件 I2C -> 带序号与时间戳的采样缓冲 -> 标定、滤波、主频、RMS
         -> 启停、接触、结果有效性 -> 串口与 LED
```

可以继续作为实板联调的主版本，不需要推倒重写。主要差距在异常情况下的数据可信度、接触识别和正式比赛输出。

| 标记 | 含义 |
|---|---|
| P1 | 优先修复：配置一致性、并发安全或正常采样问题 |
| P2 | 联调与验收前补齐：结果可信度、功能完整性或场景表现 |
| P3 | 维护改进：参数检查、文档和测试便利性 |
| 已复现 | 用真实算法源码在电脑端复现了相应行为 |
| 源码风险 | 由实现识别，发生条件还需并发模拟或实板验证 |
| 待完成/待实测 | 尚未实现，或仅凭源码不能确认效果 |

赛题公开要求包括持续振动 80~180Hz、启停频率 0~3Hz、接触识别、TTL 串口和指示灯。误差不超过 ±2Hz、识别延迟不超过 0.5s 是本组工程目标，不是目前公开命题已经明确的考核标准；最终以现场发布要求为准。

继续使用 `Wire` 硬件 I2C：SDA=GPIO8、SCL=GPIO9。软件模拟 I2C 不能解决本文中的标定、状态判断或采样同步问题。

## 3. 优先修复问题

### Q1 [P1 / 已复现] 标定结果部分替换，失败后可能混用新旧参数

位置：`dsp.cpp:230` 的 `calBias()`、`dsp.cpp:258` 的 `dspCalibrate()`、`state.cpp:100` 的 `stateApplyCal()`、`vibmon_v2.ino:44`。

**现象：** 阶段 A 直接修改全局 `s_cal.bias`，阶段 B 失败时没有恢复。新偏置可能搭配旧噪声阈值，与“沿用上次阈值”的提示并不等价。补测中标定返回失败，Z 轴偏置却从 1000mg 变为 500mg。质量不合格时仍设置 `ok=true` 并应用新参数，质量检查目前主要是提示。

**需要补充：**

1. 用候选标定保存阶段 A、B 结果，全部成功且质量合格后统一提交。
2. 阶段 B 使用候选偏置，不在中途污染当前生效标定。
3. 检查样本数、阶段 A 静置质量、阶段 B 噪声/异常/削顶和参数有限性。
4. 失败完整保留上次有效配置；区分“本次尝试失败”与“当前仍有有效标定”。
5. 首次无有效标定时，明确要求重标定或允许默认配置的策略；使用默认配置不能标为已标定。

**验收：** 阶段 A 失败、阶段 B 失败、标定中晃动或掉线均不部分替换配置；成功后的偏置、噪声与阈值来自同一次标定。

### Q2 [P1 / 源码风险] 固定等待 2ms 不能保证采样回调退出

位置：`sampler.cpp:19` 的 `onTick()`、`sampler.cpp:56` 的 `samplerStop()`、`mpu.cpp` 总线操作。

**现象：** 停定时器后仅 `delay(2)`，当前 I2C 超时却为 5ms。不能据此保证已执行的回调结束；清缓冲、标定或重初始化总线可能与旧回调重叠。`volatile` 本身不是任务同步机制。

**需要补充：**

1. 禁止新采样后，等待正在执行的操作明确完成，再返回“已停止”。
2. 等待要有超时，超时进入故障处理，不能继续重置共享数据或重配总线。
3. 使用明确同步握手；若改为专用采样任务，定时器只通知任务，由任务确认停止。
4. 缓冲索引建立同步规则，例如原子索引或短临界区；不要把阻塞 I2C 放进临界区。

**验收：** 慢读/超时期间反复停止、标定和重连，停止返回后无旧样本入队，无并发总线重配，无缓冲错乱。

### Q3 [P2 / 已复现] 缺样没有通知状态层

位置：`vibmon_v2.ino:81`、`dsp.cpp:84` 的 `dspOnGap()`、`state.cpp:123` 和 `state.cpp:139`。

**现象：** 缺样只重置 DSP 主频窗口，不清状态层的主频有效标志、启停历史或接触确认。旧主频可保持到 300ms 超时；缺口内可能漏掉启停边沿，旧周期却仍参与统计。补测确认单次缺样后主频仍有效，较大缺口后启停频率也仍有效。小缺口能否保留周期，应明确规定。

**需要补充：**

1. 增加状态层不连续通知，例如 `stateOnGap()`。
2. 立即使受影响主频失效并清零，完整连续窗口生成后才能恢复。
3. 打断启停高/低阈值连续确认和接触候选确认，不能跨缺口累计“连续”。
4. 大缺口清除周期历史；小缺口保留历史时给出依据与有效性规则。
5. 幅值和接触结果明确是否可信，必要时区分“未知”和数值 0。
6. 区分缺样与时间抖动；当前时间异常统一计为缺 1 点，不能反映真实缺口时长。

**验收：** 缺样后不再标记旧主频为有效；边沿不跨较大缺口计周期；缺口前后的观察不拼成连续确认。

### Q4 [P2 / 待实测] 接触判据仍与姿态、振动混淆

位置：`dsp.cpp:176` 姿态支路、`state.cpp:87` 的 `ctStep()`、`config.h` 的 `CT_MODE`。

**现象：** 默认判据是“姿态偏差或振动中”。低通、滞回和确认时间改善抖动，但没有改变可观测信息的局限。一直接触且姿态不变，振动暂停可能判为未接触；不接触但转动手指可能判为接触。合成 0.5Hz 启停输入已观察到停止阶段 `contact=0`，但合成输入没有独立物理接触信息。

**需要补充：**

1. 最终贴合结构上采带人工标签的数据：接触、保持、释放、无接触转动、周期振动停止阶段。
2. 明确平台的接触场景是否有可观测的振动传递或机械变化特征。
3. 根据数据确定保持/释放规则，不能直接将振动暂停判为释放。
4. 若加速度计无法区分静止接触和静止未接触，在方案中说明边界，不能保证调阈值就能解决。
5. 不得擅自添加清单外器件；硬件变化必须先确认赛题与物料限制。

**验收：** 暂停振动不把仍保持的接触误判为释放；无接触姿态变化不频繁误报；按实际考核场景记录误判、漏判和延迟。

## 4. 待补充功能与安全措施

### A1 [P2 / 待完成] 独立比赛 UART 与正式协议

位置：`output.cpp:9`、`output.cpp:23`、`output.cpp:119`。

当前为 `Serial` 调试绘图。开启 USB CDC 后全部输出走 USB，不同时发送到 GPIO21/20 比赛接口。比赛帧未实现是开发阶段未完成项，不能把绘图格式当作官方协议。

- 独立、固定初始化比赛 UART，TX=GPIO21、RX=GPIO20，不受 USB CDC 设置影响。
- USB 保留调试用途；电脑不接收不得影响比赛 UART 或采样。
- 确认波特率、帧头、字段、单位、更新率、校验与无效值表达后实现正式帧。
- 主频、振动、启停频率、接触分别表达，按协议支持有效性与故障/标定状态。
- “未确立”与“测得 0Hz”明确区分，比赛口不能混入横幅、标定、帮助或绘图文字。

**验收：** CDC 开/关两种配置下比赛口都可用；上下位机字段、单位、校验一致。

### A2 [P1 / 源码风险] 定时器启动失败没有反馈

位置：`sampler.cpp:41` 的 `samplerStart()`、`vibmon_v2.ino:34` 的 `startRun()`。

忽略定时器创建和启动返回值，之后直接标为运行。失败可能暂时显示传感器在线、绿灯正常，直到无样本超时。

- 检查创建、启动、停止返回值并向主程序报告。
- 成功启动后才设置运行标志，失败立即故障处理。
- 补创建失败、启动失败、重复启动测试。

**验收：** 注入失败后无正常运行假象、无无效句柄操作，错误原因可定位。

### A3 [P2 / 待补充策略] 削顶只有统计，没有参与可信度判断

位置：`dsp.cpp:156`、`dsp.cpp:166`、`state.cpp:130`。

`winClip` 已生成但状态层未使用。计数每次出窗口后清零，更接近更新区间计数，而不是完整滑动 128 点窗口内的计数。补测削顶仍有有效主频，这不一定意味着频率错，但幅值已经不可靠。

- 明确质量策略：削顶幅值失效，主频降级或严重削顶时失效。
- 若定义为窗口计数，同步维护滑动窗口计数；否则改名称与说明。
- 切换量程时同步灵敏度并重新标定。

**验收：** 削顶有质量标记，幅值不冒充真实值；不同量程换算正确。

### A4 [P2 / 待实测] 采样时序与输出负载

位置：`sampler.cpp:19`、`sampler.cpp:69`、`output.cpp:33`、`output.cpp:84`。

共享 `esp_timer` 任务仍执行阻塞 I2C；三轴波形在主循环逐样本打印。USB 带宽较高不等于绝不阻塞。时间戳是读取完成时刻，不是传感器产样时刻；间隔正常也不能证明没有重复或漏读。

- 记录读耗时、间隔、主循环耗时和缓冲最高占用的平均值与最大值。
- 调试输出限流/抽取/块缓冲，满时丢调试数据，不阻塞核心测量。
- 比较调试关闭、结果绘图、三轴波形、电脑不读取时的缺样与频率表现。
- 如时钟不同步导致不稳，考虑 FIFO；当前 INT 未接也能采用 FIFO 轮询。
- 200kHz 验证连续采样；100kHz 便于调通；400kHz 先确认上拉、布线与波形。
- 实测 SDA/SCL 电平符合 3.3V IO 域，软件配置不能代替电平检查。

**验收：** 正常运行无持续溢出，调试阻塞不会长时间阻碍测量、故障检查或命令响应。

### A5 [P3 / 待补充] 参数边界与说明一致性

- 编译期检查采样率大于 0、缓冲长度有效、窗口与步长关系正确、索引类型容纳包络长度。
- 检查 DLPF、量程与滤波频率合法性，测频上限低于当前采样率的奈奎斯特频率。
- 保证 `SS_MIN_PERIODS <= SS_USE_PERIODS <= SS_EDGE_MAX`，确认计数不溢出。
- `ENV_WIN`、`ENV_HOP` 是样本数，1000Hz 改 500Hz 后包络时间和确认时间都会变长，须同步核对。
- 当前最大启停周期 10 秒，对应最低非零频率约 0.1Hz；更低频率需要延长观察，不能笼统宣称覆盖任意非零频率。
- 内部 60~220Hz、启停周期下限 200ms 是容错范围，不是官方测量范围，对外越界行为要明确。
- 修改后同步 README、协议和方案，不把“函数已实现”写成“实物已达标”。

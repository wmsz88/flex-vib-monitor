| 版本 | 目录 | 是什么 | 编译产物 |
|---|---|---|---|
| v5 | `vibmon_v5\` | 历史默认版。**当前工作区实际配置是 `CT_HOLD_ENABLE=1`（启停保持门）+ T011 进入路径 + `SS_HI_MG/SS_LO_MG = 120/80`**，不是早期文档写的「hold 关默认版」 | `vibmon_v5\_probe\t011\build_uart_b\`（SHA `e945d958…`） |
| v6 | `vibmon_v6\` | 接触三条候选版：①收拢并停下才算接触 ②接触后不再看加速度 ③只有陀螺判出张开、或进入后又转过 `CT_RELEASE_DEG` 才分离。另含「接触中启停取最新一致段」与起振门 `120/80` | `vibmon_v6\build_uart\` |

**编译方法**：arduino-cli 的 `--build-path` 不能含中文，本机采用的写法是先把 `vibmon_v6\` 的 `*.ino`、`*.h`、`*.cpp` 拷到一个英文临时目录（文件夹名保持 `vibmon_v6`），再

```bash
arduino-cli compile --fqbn esp32:esp32:esp32c3 --warnings all "<英文临时目录>/vibmon_v6"
```

产物 `.bin` 拷回 `vibmon_v6\build_uart\`。

> ⚠️ ESP32 的 `.bin` 里嵌了编译时刻，**同一份源码两次编译的 SHA-256 不同**（实测两次 0 warning 构建差 68 字节，全落在头部描述区与末尾指纹段）。要认定「这是同一个固件」请用 git 提交 + 源码哈希，别拿 `.bin` 的 SHA 当判据。

## 三、编译与烧录

### 3.1 编译环境

- Arduino IDE 2.x，开发板管理器装 **esp32 by Espressif**（本机实测 **3.3.12** 通过）
- 板子选 **ESP32C3 Dev Module**（FQBN `esp32:esp32:esp32c3`）
- 本项目两份代码均已在 `--warnings all` 下**零警告**编译通过：
  - selftest：Flash 25%（340 KB / 1280 KB），静态 RAM 4%（15 KB）
  - vibmon：Flash 25%（337 KB），静态 RAM 7%（23 KB）

命令行编译（可选，比开 IDE 快）：

```bash
arduino-cli compile --fqbn esp32:esp32:esp32c3 --warnings all "D:/大学/课程/工创赛/代码/vibmon"
```

### 3.2 进下载模式（组委会模块的 BOOT/RESET 组合键）

```
按住 BOOT  →  按一下 RESET  →  松开 RESET  →  松开 BOOT
```

然后用 USB Type-C 线连电脑烧录。串口监视器设为 **115200 / 8N1**。

> 若勾选 "USB CDC On Boot"，`Serial` 会变成 USB-CDC 口，固件会自动把调试信息镜像过去
> （代码里用 `ARDUINO_USB_CDC_ON_BOOT` 自动判断，不用手改）。
> **比赛口恒为 `Serial1` → GPIO20/21 → 4PIN 焊盘**，与 USB 口互不影响。

### 3.3 建议的验证顺序

1. 先在**成品 ESP32-C3 开发板 + 独立 MPU6050 模块**上跑通（不必等柔性板制回来）。
2. 焊好的柔性板上跑 `selftest`，拿结果去返工。
3. 全 PASS 后烧 `vibmon`，按 `代码\MPU6050寄存器速查.md` 第八节调 I2C。
4. 柔性板回来后**只需确认引脚宏不用改**（网表已一致）并重做标定。

## 四、上电前必做的三个万用表检查

这三项**软件测不出来**，但每一项都能决定板子会不会烧：

| # | 检查 | 判据 | 不正常怎么办 |
|---|---|---|---|
| 1 | SDA/SCL 对 GND 的**空闲电压** | **≤ 3.3V** | 约 5V 立刻断电：把 MPU 模块 VCC 从 +5V 改接 ESP32 模块的 **3V3 脚** |
| 2 | 滑动开关**断开**后测 5V 轨 | **0V**，红 LED 灭 | 仍有电 → 存在反向馈电，违反赛题「断开零静态功耗」 |
| 3 | 12V 输入端对 GND 电阻（开关开时） | 不应接近 0Ω | 接近短路 → 查 `SW1.3` 是否真是不该接 GND 的电气触点 |

> 第 1 项的依据：命题表2 只写 MPU6050 模块「内置 5.1K 上拉」，**没说上拉到哪一档**。
> ESP32-C3 的 IO 绝对最大只有 3.6V，若被上拉到 5V 会伤 IO。软件无法区分二者
> （5V 经 ESD 钳位后数字上仍判为高，且 GPIO8/9 不属于 ADC1），所以只能实测。

## 五、两份程序各自在干什么

### 5.1 `selftest.ino` —— 13 项自检

| # | 检查项 | PASS 判据 |
|---|---|---|
| 01 | 复位原因 | 非 BROWNOUT / PANIC / WDT |
| 02 | 电源与红 LED | 红 LED 常亮（目视） |
| 03 | 三灯 | 绿/黄各闪 3 次（目视） |
| 04 | 串口 | banner 可见 + 回显输入字符 |
| 05 | I2C 空闲电平 | GPIO8/9 均为 HIGH |
| 06 | **上拉电平风险** | 万用表实测 SDA/SCL ≤ 3.3V |
| 07 | I2C 扫描 | 恰好命中 **0x68** |
| 08 | WHO_AM_I | 读回 **0x68** |
| 09 | 寄存器回环 | 写 `PWR_MGMT_1=0x00` 回读一致 |
| 10 | 六轴 + 温度 | 静止时 `|a| ≈ 1000mg` |
| 11 | 静置零偏标定 | 打印 bias 与 σ，并给出建议阈值 |
| 12 | **I2C 压力测试** | 1000 次读平均 **< 500µs**、错误 0 |
| 13 | 线序 / 断电确认 | 人工比对 |

第 12 项是 `vibmon` 里 `I2C_CLOCK = 200000` 这个取值的**实测验证点**。
平均耗时 > 900µs 或出现错误，就把 `I2C_CLOCK` 降到 `100000`，同时把 `FS_HZ` 降到 `500`。

运行中可用命令：`?` 帮助 ｜ `s` 重新自检 ｜ `c` 重做零偏标定 ｜ `m` 再读六轴

### 5.2 `vibmon.ino` —— 振动检测主程序

```
esp_timer 1kHz 回调 ──读MPU 6字节──► 环形缓冲(512)
loop()：环形缓冲 ─► 去直流 ─► 二阶高通(70Hz) ─► 三轴合成包络(RMS 30ms)
        ├─ 100Hz：双阈值滞回 + 3次确认 ─► 启停状态机 ─► 启停频率(0~3Hz)
        ├─ 每64点：滞回过零 + 线性插值 + 周期中位数 ─► 主频(80~180Hz)
        └─ 50Hz：组 $VD 帧 ─► UART 输出（发送永不阻塞采样）
```

| 决策 | 取值 | 理由 |
|---|---|---|
| 采样率 | **1kHz** | 满足赛题「≥500Hz，建议 1kHz」；官方原文确认加速度输出率恒为 1kHz，读不重不漏 |
| I2C 速率 | **200kHz** | 读 6 字节约 0.42ms，落在 1ms 周期里余量 2.4×。400kHz 虽更快，但在 5.1k 上拉下要求总线电容 ≤69pF，而 30cm 杜邦线 + 跨弯曲区走线很容易超 |
| 只读加速度 | **6 字节** | 陀螺仪/温度对振动检测无用，省掉一半 I2C 时间 |
| 高通截止 | **70Hz / Q=0.707** | 80Hz 处仅 -2.0dB，50Hz 工频 -6.8dB；测频率只看过零点，幅值微降不影响 |
| 主频算法 | **滞回过零 + 线性插值 + 周期中位数** | 插值不受 `fs/N` 限制：N=128 时 FFT 的 Δf 是 7.8Hz，而插值可到亚 Hz。中位数对偶发噪声免疫 |
| 自动选轴 | 取交流能量最大的轴 | 柔性板贴在手指上姿态不定，固定用 Z 轴会漏检 |
| 启停确认 | **3 个包络点 = 30ms** | 远小于赛题 0.5s 预算，留 3× 以上余量 |
| 帧率 | **50Hz** | 3Hz 启停周期内有 16 帧，够用 |

**黄 LED 语义**：赛题只要求「预留可控」，本程序赋予它「检测到持续振动时常亮」的含义。

命令字：`?` 帮助 ｜ `c` 重做标定 ｜ `z` 打印阈值 ｜ `S` 状态摘要 ｜ `d` 调试行开关 ｜ `R` 原始 dump ｜ `n` 清零统计

## 六、可调参数速查（都在 `.ino` 顶部配置区）

| 宏 | 默认 | 什么时候改 |
|---|---|---|
| `I2C_CLOCK` | `200000` | selftest 第 12 项不过 → 改 `100000` |
| `FS_HZ` | `1000` | 跟着上一项一起降 `500`；或发现采样拍频异常改 `900` |
| `BAUD` | `115200` | 平台要求别的波特率 |
| `UART_SWAP` | `0` | 与平台接线确认无误仍不通 → 改 `1` |
| `REG_VALUE_DLPF` | `0x00` | 想压噪声且能接受 180Hz 轻微衰减 → 改 `0x01` |
| `FREQ_ALGO` | `0` | FFT 实现填好后 → 改 `1` |
| `LED_ACTIVE_LOW` | `0` | 某灯接成灌电流驱动 → 改 `1` |
| `HP_FC_HZ` | `70.0` | 现场发现低频干扰大 → 提高到 `90`；发现 80Hz 幅值偏低 → 降到 `50` |

## 七、已知的硬件遗留问题，哪些影响固件

| 遗留问题 | 影响固件？ | 说明 |
|---|---|---|
| `SW1.3` 接 GND | **不影响** | 纯电源通路。若真是电气触点则 12V 对地短路 → 直接没电，MCU 都起不来（自检会反复报 BROWNOUT） |
| 红 LED 极性 | **不影响** | 硬件直连 5V，软件不可控，只作「5V 正常」的目视凭据 |
| ~~4PIN 线序与命题文字冲突~~ | **已解除（2026-09-29）** | 更新版赛题删除了旧正文的矛盾文字，图 3 确认 **①TX ②RX ③GND ④VIN**，与网表一致。`UART_SWAP` 保持 `0`，无需改动 |
| 绿灯 VF 上限 3.6V（更新版表1 官方规格） | **不影响固件逻辑** | GPIO10 拉电流驱动，典型 VF≈3.0V 时约 2.5mA，偏暗可辨。已决定不改板，现场预案见下 |
| GPIO2/8/9 是 strapping 脚 | **影响启动** | GPIO8/9 已被 I2C 占用，靠模块板载上拉保持高。**上电瞬间不要驱动这两个脚**，代码里 I2C 初始化前只做输入态读数 |
| MPU INT 悬空 | **影响架构** | 只能用定时器定速采样，不能用 DRDY 中断 |
| AMS1117 压差 7V、Pd≈0.4W | **影响固件** | **严禁启用 Wi-Fi/BLE**（射频峰值 300mA 会热关断）。两份代码中没有任何 `WiFi`/`BLE` 调用 |

### 绿灯现场预案（若绿灯不亮/极暗）

更新版表1 明确绿 LED VF = 2.5~3.6V @20mA，上限高于 GPIO 的 3.3V。按序执行：

1. 断电换备件绿灯（清单每色 2 颗，本设计各用 1 颗）再观察；
2. 仍不亮 → 飞线改灌电流：LED 反接（阳极→5V 轨，阴极→R7→GPIO10），R7 由 120Ω 换 360Ω（(5−3.0)/360≈5.6mA 更稳，同封装换料）；
3. 固件 `LED_ACTIVE_LOW` 改 `1` 重新编译烧录。

## 八、明确没做的事（以及为什么）

| 没做 | 原因 |
|---|---|
| Wi-Fi / BLE | LDO 热功耗会爆，见上表 |
| FFT | 本版用简易法（对 ±2Hz 反而更稳），FFT 位置已留桩在 `vibmon.ino` 里，注释写清了四步填法 |
| FreeRTOS 双任务 | `esp_timer` 回调 + 环形缓冲已经实现了「采样与算法解耦」，同样的效果但现场调试成本更低。任务划分留作**方案文档里的软件架构叙述**加分项 |
| 动态内存 / `String` | 定长缓冲（`char[240]` / `char[72]`），避免堆碎片 |
| DMP | 需要厂商固件镜像，组委会资料包里没有 |
| 运行期 TX/RX 自动交换 | 见上表第 3 项 |

# 历届比赛串口通信协议调研

> 调研日期：2026-10-31
> 来源：比赛官网 jnds.gdut.edu.cn + GitHub 公开仓库

---

## 结论

**比赛组委会从未规定串口帧格式和波特率。** 2025 年赛项1（电机检测模块）和 2026 年赛项1（柔性振动检测模块）的命题 PDF 都只写了"TTL 电平、杜邦线连接"，帧协议由参赛队自行设计、现场与测试平台对接后定。

帧长不是必须 35 字节也不是必须 33 字节。35 字节是我们自己定的（30 字节正文 + 1 逗号 + 2 位校验 + \r\n），比赛没有约束这个长度，改 64 字节或 10 字节都可以，只要平台能解析。

## GitHub 历届参赛队公开代码（参考）

### 1. NeekoNoNeko/pill-sorting-vision（2024 三等奖，药品分拣）
- **通信**：OpenMV → STM32 主控，UART 9600 8N1
- **帧格式（二进制定长 10 字节）**：
  ```
  0xAA  0xBB  color  status  quadrant  x_hi  x_lo  y_hi  y_lo  0xFF
  帧头  帧头  颜色   状态    象限      X高  X低   Y高  Y低   帧尾
  ```
- **特点**：双字节帧头 + 单字节帧尾，无校验和（短帧 + 0xAA 0xBB 已够用）
- **源码**：`vision/highTry/备份.py` `SendData.uart_send()`

### 2. SakuraHop/explorer-eod-rescue-robot（2025 一等奖，排爆救援机器人）
- **通信**：STM32F407 多路 UART，全部 **115200 8N1**
- **协议风格**：
  - 板间控制：**单字节命令**（如 `USART1_SendByte(0x01)`），简单高效
  - IMU（HWT101）：`FF AA 69 88 B5`（解锁）、`FF AA 76 00 00`（归零）、`FF AA 00 00 00`（保存）— 维特善标准协议
- **特点**：内部板间通信用极简单字节；外部 IMU 用厂商标准协议。没有自定义复杂帧格式

### 3. nanjin1/Intelligent-Delivery-Cart（2024 一等奖，智能配送小车）
- **通信**：STM32C8T6/RCT6，具体协议在电路报告 PDF 中（未公开源码细节）
- **特点**：使用 C8T6 做下位机 + RCT6 做上位机的双机架构

### 4. zhangxianggan/zongjisa-mpu6050（2026 同赛项，其他队伍）
- **通信**：ESP32-C3 UART **115200 8N1**
- **帧格式（CSV 文本行）**：`ax_g,ay_g,az_g,vibration,carrier_hz,start_stop_hz,rms_g,missed_ticks\r\n`
- **特点**：无帧头无校验，每行一个数据点，浮点直接 printf

## 我们 35 字节帧 vs 历届做法

| 对比项 | 我们的 $VD 帧 | 2024 药品分拣 | 2025 排爆机器人 | 2026 同赛项他人 |
|---|---|---|---|---|
| 类型 | ASCII 定长 | 二进制定长 | 单字节命令 / 厂商协议 | CSV 文本变长 |
| 长度 | 35 B | 10 B | 1~5 B | ~50 B/行 |
| 帧头 | `$VD` | `0xAA 0xBB` | `0xFF 0xAA`（IMU）| 无 |
| 帧尾 | `\r\n` | `0xFF` | 无 | `\r\n` |
| 校验 | XOR 2 位 hex | 无 | CRC（厂商） | 无 |
| 波特率 | 115200 | 9600/19200 | 115200 | 115200 |
| 可读性 | 串口助手可肉眼读 | 需 hex 查看器 | 需逻辑分析仪 | 串口助手可读 |
| 抗误码 | XOR 校验 | 靠帧头帧尾 | CRC16 | 靠行分割 |

**结论**：我们的帧设计（ASCII + 帧头 + XOR + \r\n）在四类参考中是**最完善的**，与历届队伍相比没有过设计。35 字节不是官方要求，是我们自己选的合理长度；如果要改 64 字节只需扩展 `compBuildFrame()` 的 snprintf 格式串并在 `comp_frame_test.cpp` 里同步更新测试用例。

## 帧长选择建议

| 长度 | 适用场景 | 建议 |
|---|---:|---|
| 10~16 B | 少量状态位 + 坐标 | 如果平台只要"有没有振动 + 接触"两个 bit，可以缩到 ~15 B |
| 35 B（当前） | 5 个测量值 + 有效性 + 校验 | 当前最合理：50Hz × 35B = 1750 B/s，115200 下占 15% |
| 64 B | 加原始三轴 + 温度 + 时间戳 | 如果平台需要加速度波形（不只是结果），扩到 64 B |
| >64 B | 逐样本数据流 | 用单独的 debug 模式（`#` 前缀 CSV），不走比赛帧 |

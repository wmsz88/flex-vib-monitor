# v6 → v7 逐行讲解（每个模块改了什么、每一处为什么改）

> 日期：2026-11-08
> 对比基准：`代码\vibmon_v6\`（T013 上板验收的出发版）→ `代码\vibmon_v7\`（现场适配参考版）
> 结论一句话：**v7 = v6 接触三条（判据链一行未动）+ 黄灯/`y` 命令 + 三只现场预案宏**。
> 实质改动只有两个文件：`config.h` 与 `output.cpp`。以下每个改动都给「模块 + 位置 + 逐行讲什么 + 作用」。

## 0. 为什么要有 v7

`vibmon_v6` 是已经上板验收过的版本，现场纪律是「改了的代码」和「验过的代码」不混在一起。
所以把 T010 的黄灯语义改动和三只现场预案宏单独放进 `vibmon_v7`，v6 原样归档当回退底牌。

## 1. 版本角色与没动的文件

| 版本 | 角色 |
|---|---|
| vibmon_v6 | 最终版 / 出发版（上板验收过，归档不动） |
| vibmon_v7 | 现场适配参考版（本文主角） |

逐字节相同的文件（判据链，出问题不许现场改）：

- `state.cpp` / `state.h`：启停与接触状态机
- `dsp.cpp` / `dsp.h`：滤波、包络、频率
- `posture.cpp` / `posture.h`：开合角
- `sampler.cpp` / `sampler.h`：采样定时
- `mpu.cpp` / `mpu.h`：MPU6050 驱动
- `vibmon_v7.ino`：与 `vibmon_v6.ino` 逐字节相同（只换文件名，内容零改动）

换句话说：**v7 的所有区别都在「输出侧」，传感、滤波、判定全部原封不动**，
所以 v7 的宿主测试基线与 v6 完全一致（contact 89/89、gyro 8/8、comp_frame 22/22、dump 15/19 既有列数问题、ss_replay 可运行），只多了 `led_test` 64/64。

## 2. `config.h`（配置头）—— 新增 3 只预案宏 + 配套参数检查

### 2.1 三只现场预案宏（位置：`config.h:61-70`，插在 `COMP_FRAME_CL` 块之后、MPU6050 段之前）

逐行讲（v7 新增的 3 组定义，全部用 `#ifndef` 包住，允许 `-D` 命令行覆盖）：

- `COMP_FRAME_CSV`（`config.h:62-64`），默认 `0`
  - 作用：`1` 时比赛口不再发 `$VD` 二进制帧，改发 CSV 文本行 `ct,vib,freq,amp,ss`（CRLF 结尾）。
  - 为什么默认 `0`：出发版必须保持原字节流不变，现场平台要什么格式再现场翻开关。
- `COMP_FRAME_DIV`（`config.h:65-67`），默认 `1`
  - 作用：发送分频。`1` = 50Hz 原速；`2` = 25Hz；`5` = 10Hz。
  - 注意点：只降帧率，**SEQ 仍逐帧连续**（减一后再发），所以按 SEQ 判丢帧的平台不会误报。
- `COMP_FRAME_GATED`（`config.h:68-70`），默认 `0`
  - 作用：`1` 时比赛口变成命令触发式：收到 `'S'`（或小写 `'s'`）才开始发，收到 `'X'`（或 `'x'`）停止，上电默认静默。

三者都不在判据链上，只影响比赛口的输出形式。

### 2.2 配套的编译期参数检查（位置：`config.h:738-749`，在 `COMP_PERIOD_MS` 检查之后）

逐行讲：

- `COMP_FRAME_CSV` 只能是 0 或 1，否则 `#error`。
- `COMP_FRAME_DIV` 必须 >= 1（`#if (COMP_FRAME_DIV < 1)` 报错）。
- `COMP_FRAME_GATED` 只能是 0 或 1。
- `COMP_FRAME_GATED=1` 且 `COMP_FRAME_ENABLED=0` 时直接编译报错——门控没有意义，因为比赛帧根本不发送。

作用：现场改宏时，配错（比如 DIV 填 0、门控和关帧冲突）在编译期就拦住，而不是烧上板才发现比赛口没了。

## 3. `output.cpp`（输出与命令）—— 黄灯三态 + `y` 命令 + 三预案实现 + 状态行/帮助行

### 3.1 黄灯三态（T010 改动 A）

**作用一句话：把「黄灯 = 振动中常亮」改成「黄灯 = 接触中 2Hz 闪」，并且可以用 `y` 命令演示可控亮灭**（赛题只要求黄灯「预留并可控制亮灭」，接触闪最直观）。

逐处讲：

1. 状态变量（位置：`output.cpp:32-34`，注释块 27-31 讲语义，紧跟 `static LedMode s_led = LED_RUN;` 之后）
   - `enum LedYMode { LEDY_AUTO, LEDY_ON, LEDY_OFF, LEDY_COUNT };`
   - `static uint8_t s_ledY = LEDY_AUTO;`
   - `static const char* const kLedYName[LEDY_COUNT] = { "AUTO", "ON", "OFF" };`
   - 三态含义：AUTO = 跟随接触（CT=1 时 2Hz 闪、CT=0 灭）；ON = 常亮；OFF = 常灭。只在 `LED_RUN` 下生效；`LED_FAULT`（4Hz 快闪）与 `LED_CAL` 一律不受影响。
2. `ledUpdate()` 的 `LED_RUN` 分支（位置：`output.cpp:772-782`）
   - v6 原来是一行：`ledWrite(PIN_LED_Y, r.vib == 1);`
   - v7 换成 `switch (s_ledY)`：`LEDY_ON` 直接亮；`LEDY_OFF` 直接灭；default（AUTO）里写
     `ledWrite(PIN_LED_Y, (r.contact == 1) && (((nowMs / 250) & 1) != 0));`
     ——接触中每 250ms 翻转一次，正好 2Hz；不接触则恒灭。
   - 注释同步改成「绿 1Hz 心跳；黄 = 接触中 2Hz 闪（y 命令可切常亮/常灭）」。
3. `outPollCmd()` 新增 `case 'y'`（位置：`output.cpp:906-911`，插在 `case 'd'` 之后）
   - `s_ledY = (s_ledY + 1) % LEDY_COUNT;` 然后 `outPrintf("[LEDY] %s\n", kLedYName[s_ledY]);`
   - 作用：按一次 `y` 循环 AUTO → ON → OFF → AUTO，并回显当前态，手动演示时不用重编译。
   - 设计取舍：手动态优先于自动联动；黄灯不在 `$VD` 数据路径上，所以不做门控宏。
4. `outPrintStatus()` 末尾加一行（位置：`output.cpp:412-413`，在 `outPrintCal()` 之前）
   - `黄灯 [LEDY] AUTO（y 切换：AUTO 接触中2Hz闪 / ON 常亮 / OFF 常灭）`
   - 作用：`S` 状态行能直接看出黄灯现在处于哪个模式。
5. 帮助行（位置：`output.cpp:874`）
   - 「`d 调试行 | S 状态 | c 重标定 | n 清零统计`」后追加 `| y 黄灯`。

配套宿主测试：`test\led_test.cpp`（v7 新增，位置：`test/led_test.cpp:1-168`），跑 `led_test.exe`，断言 64/64：验证 AUTO 模式 CT=1 时黄灯 2Hz 翻转、CT=0 恒灭、ON/OFF 三态、FAULT/CAL 不受 `s_ledY` 影响。

### 3.2 预案 #1：CSV 文本行

**作用一句话：平台不认 `$VD` 二进制帧、只认 CSV 文本行时，改一只宏就切过去。**

逐处讲：

1. 编码函数整段收进 `#if !COMP_FRAME_CSV ... #endif`（位置：`output.cpp:97-139`，包住 `encFreqX10()` 到 `xorChk()`）
   - 原因：CSV 模式下这些编码函数用不到，不包会被 `-Wall` 报「定义了未使用的静态函数」。v6 里没有这层包裹，因为不存在 CSV 模式。
2. `compBuildFrame()` 开头加 CSV 分支（位置：`output.cpp:158-171`，在 `if (!out || outSize < COMP_OUT_MIN) return -1;` 之后）
   - `#if COMP_FRAME_CSV` 分支里：先做 `isfinite` 防护（无效量照旧发 0，与 `$VD` 同量纲），然后一条
     `snprintf(out, outSize, "%u,%u,%.1f,%u,%.2f\r\n", ct, vib, freq, amp, ss);`
   - `(void)seq;`：CSV 行里没有 SEQ 字段，显式吞掉参数避免 `-Wall` 告警。
   - 返回写出的字节数（含 CRLF）。
   - `#else` 后面是 v6 原来的 `$VD` 帧拼装（`$VD,SEQ,...,VALID,CHK`），一字未改。
   - `#endif   // COMP_FRAME_CSV` 收尾（`output.cpp:194`）。
   - 作用：平台要的列序/位数不同，现场只需要改这一条格式串，不用动别处。
3. 开机横幅（位置：`output.cpp:251-253`，`outPrintBanner()` 里）
   - `#if COMP_FRAME_CSV` 打一行 `[COMP] CSV 文本行模式：ct,vib,freq,amp,ss（无帧头无校验）`。
   - 作用：上电第一眼就能确认当前比赛口是哪种模式，不用拿逻辑分析仪猜。

实测样例（`C:\Users\Lenovo\vibmon_drill\` 冷编译链路）：
`CSV SAMPLE: len=20 [1,1,165.2,966,1.20`，即 `ct=1, vib=1, freq=165.2Hz, amp=966mg, ss=1.20Hz` + CRLF = 20 字节。
注意：切 CSV 后 `comp_frame_test` 的 22 项断言（断的就是 `$VD` 帧格式）按定义会失败，这不是 bug；现场要么跳过该项，要么另配 CSV 断言。

### 3.3 预案 #2：发送分频

**作用一句话：平台嫌 50Hz 太快时，把帧率降到 25Hz 或 10Hz，只改宏。**

逐处讲：

1. 状态（无需新增变量，`compPeriodic()` 里的 `lastMs` 就是节拍器）。
2. `compPeriodic()` 节拍判断（位置：`output.cpp:211`）
   - v6：`if ((uint32_t)(nowMs - lastMs) < (uint32_t)COMP_PERIOD_MS) return;`（`COMP_PERIOD_MS=20`，即 50Hz）
   - v7：同一行把周期换成 `(uint32_t)(COMP_PERIOD_MS * COMP_FRAME_DIV)`。
   - 作用：`DIV=2` 时周期 40ms = 25Hz；`DIV=5` 时 100ms = 10Hz。发送里 SEQ 仍然每发一帧 +1，只是发得稀了，平台不会因跳号判丢帧。
3. 开机横幅（位置：`output.cpp:254-257`）
   - `#if COMP_FRAME_DIV > 1` 打 `[COMP] 发送分频 %d：帧率约 %d Hz`。

### 3.4 预案 #3：命令门控（收 'S' 发 / 收 'X' 停）

**作用一句话：平台要求「先发启动命令才开始推流」时，改一只宏就接上。**

逐处讲：

1. 门控状态（位置：`output.cpp:82-84`，在 `s_compSeq` 之后）
   - `#if COMP_FRAME_GATED` + `static bool s_compGated = false;` + `#endif`
   - 作用：记住比赛口当前是被允许发还是被命令停了；编译期开关关掉时这个变量根本不存在，零开销。
2. `compPeriodic()` 开头读口（位置：`output.cpp:200-209`，在 `if (!s_compReady) return;` 之后、节拍判断之前）
   - `while (Serial1.available())` 把比赛口缓存里的字节读干净；
   - `gc == 'S' || gc == 's'` → `s_compGated = true;`；`gc == 'X' || gc == 'x'` → `s_compGated = false;`
   - `if (!s_compGated) return;`——门没开就直接返回，一帧都不发。
   - 实操记录里脚本为保持 ASCII 写成 `0x53/0x73/0x58/0x78`，与 `'S'/'s'/'X'/'x'` 等价。
   - 作用：比赛口自己就能被平台遥控，不占调试口的 `S`（状态）/`X` 命令位。
3. 开机横幅（位置：`output.cpp:258-260`）
   - `#if COMP_FRAME_GATED` 打 `[COMP] 命令门控：收到 'S' 开始发、'X' 停止（上电默认静默）`。

### 3.5 继承自 v6 的接触三条（v7 一字未改，但要背）

| 宏（`config.h` 位置） | 默认 | 作用 |
|---|---|---|
| `CT_V6_ENABLE` | 1 | 0 = 回到 v5 + T011 行为 |
| `CT_SETTLE_ENABLE` | 1 | 0 = 不要求手指停下 |
| `CT_SETTLE_DPS` / `CT_SETTLE_MS`（`config.h:402-403` 附近） | 10.0f / 150 | 停下门限：滤波后合成角速度低于 10 dps 且持续 150ms 才算「停」 |

现场最容易用到的参数改动是 `#5`：手指已停但一直不进接触时，把 `CT_SETTLE_DPS` 由 `10.0f` 改 `15.0f`（编译 0 warning，宿主测试与基线一致）。

## 5. 一页速记（现场问「v6 怎么到 v7」就答这段）

- 判据链（state/dsp/posture/sampler/mpu）逐字节相同，v7 只动输出侧。
- `config.h`：+3 只预案宏 `COMP_FRAME_CSV / COMP_FRAME_DIV / COMP_FRAME_GATED`（默认 0/1/0，出发字节流零变化）+ 4 条参数检查。
- `output.cpp`：
  1. 黄灯改接触联动（CT=1 时 2Hz 闪）+ `y` 命令三态 AUTO/ON/OFF，状态行与帮助行同步；
  2. `compBuildFrame()` 加 CSV 分支（`ct,vib,freq,amp,ss`），编码函数收进 `#if !COMP_FRAME_CSV`；
  3. `compPeriodic()` 周期乘 `COMP_FRAME_DIV`（分频）；
  4. `compPeriodic()` 开头收 `'S'`/`'X'`（门控），上电默认静默；
  5. 横幅按三宏各打一行提示。
- 测试：v6 基线 + 新增 `led_test` 64/64；全部 0 warning；7 个预编译变体在 `_variants\`（def/cl/csv/div2/gate/v5sem/uart）。
